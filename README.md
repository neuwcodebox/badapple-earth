# Bad Apple Earth

Bad Apple!!의 각 프레임과 형태·명암이 닮은 **실제 위성·항공사진 한 장**을 찾아 영상을 재구성하는 로컬 제작 도구다. 그림을 새로 생성하거나 여러 장소를 합성하지 않고, 실제 지구에서 촬영된 장면 자체를 검색한다.

> **현재 상태: 설계·개발 인계 준비 완료, 프로그램 구현 전.** 이 패키지는 개발 하네스와 프로젝트 문서만 포함한다. 실행 가능한 애플리케이션, 설치용 패키지, 이미지 데이터셋, 결과 영상은 아직 없다.

## 주요 기능과 목표

구현 목표는 공개 영상 데이터의 수집·전처리·검색·재추출·MP4 렌더링을 독립적으로 반복 실행하는 파이프라인이다. 우선 1만 후보로 10초 영상을 만들어 실제로 형태가 보이는지 확인하고, 그 결과를 근거로 데이터셋을 확대한다. 개별 프레임의 장소가 계속 달라지는 것은 허용하며, 캐릭터·배경의 연속성은 목표가 아니다.

최초 비교 결과는 컬러 사진 버전을 기준으로 한다. 흑백·원본과 나란히 보기·명암 특징 비교도 평가에 사용한다. 기본 결과의 각 프레임은 하나의 실제 장소이며, 포토모자이크는 별도 합의 없이 기본 방식으로 바꾸지 않는다.

## 시작하기

### 1. 원본 MP4 준비

사용자는 원본 영상을 **이미 MP4 파일로 가지고 있다.** 다운로드 기능, YouTube 검색, 영상·음원 재확보는 필요하지 않다.

압축을 푼 `badapple-earth/` 안에 `input/` 디렉터리를 만든 후, 보유한 파일을 `input/badapple.mp4`에 두는 것을 권장한다. 원본 파일을 이동하고 싶지 않으면 구현 시 다른 로컬 경로를 지정해도 된다. 원본은 읽기 전용 입력으로 취급하고 덮어쓰지 않는다.

**MP4는 이 ZIP에 들어 있지 않다.** 파일이 아직 전달되지 않았다면 해당 입력이 필요한 검증만 차단 상태로 남기고, 데이터 수집기·저장소·테스트 구현은 진행할 수 있다. 대체 영상을 임의 다운로드하거나 원본을 확인했다고 보고하지 않는다.

### 2. 개발 환경

Python 3.11 이상과 FFmpeg/ffprobe를 사용하는 CPU 기반 로컬 도구로 설계했다. Linux/WSL2를 기준으로 시작하며 Windows 네이티브 지원은 의존성 설치를 실제 확인한 뒤 표시한다. GPU·클라우드 서버·LLM API 키는 필수가 아니다. 구체적인 의존성 선택과 버전 고정은 [TECH의 실행 환경](docs/TECH.md#실행-환경)을 따른다.

현재는 `pyproject.toml`, lockfile, 실행 CLI가 없으므로 이 저장소에 `pip install -e .`나 애플리케이션 실행 명령을 적용할 수 없다. 구현자가 패키지와 설치 절차를 검증한 뒤 이 절에 실제 사용법을 추가한다.

FFmpeg를 별도로 설치했고 MP4를 배치했다면, 아래 **외부 도구 명령**으로 입력 메타데이터를 확인할 수 있다. 프로젝트 프로그램의 실행 명령은 아니다.

```bash
ffprobe -v error -show_format -show_streams -of json "input/badapple.mp4"
```

길이·영상 스트림·오디오·프레임레이트·픽셀 종횡비를 확인하고, 검은 여백이 실제 콘텐츠인지 레터박스인지 여러 시점의 프레임으로 판단한다. MP4의 길이, 오디오 유무, 4:3 여부는 아직 확인되지 않았다.

## 사용 방법

구현 후의 기본 흐름은 다음과 같다. 현재는 실행 명령이 아니라 사용 시나리오다.

1. 로컬 MP4에서 실제 콘텐츠 비율과 테스트할 10초 구간을 확정하고 6fps로 샘플링한다.
2. Sentinel-2에서 지형이 다양한 후보를 수집하고 품질·좌표·특징량을 저장한다.
3. 1만 후보에서 Top-K를 검색해 비교 시트와 10초 컬러 결과를 만든다.
4. 동일한 목표 프레임을 유지하며 10만 후보와 비교한다. 확장 여부는 점수와 실제 재생 결과로 정한다.

데이터 수집에는 인터넷 연결이 필요하다. 실제 서비스의 접근·비용 조건을 확인하고, 과금 서비스나 AWS Requester Pays를 사용자 승인 없이 활성화하지 않는다. 공개 데이터라는 사실과 다운로드 경로가 무료라는 사실은 별개다. [TECH의 소스별 접근 조건](docs/TECH.md#2-외부-데이터-소스)을 확인한다.

## 개발 이어가기

다른 AI 또는 개발자는 **`AGENTS.md` → `docs/PLAN.md` → `docs/SPEC.md` → `docs/TECH.md`** 순서로 읽고 P1부터 진행한다. 이전 대화는 필요하지 않다.

다음 내용을 그대로 작업 지시로 사용할 수 있다.

```text
이 워크스페이스의 AGENTS.md와 docs/PLAN.md를 먼저 읽고, SPEC의 F/N 요구사항과
TECH의 설계를 따라 P1부터 구현하라. 기본 콘셉트는 프레임당 실제 장소 사진 한 장이다.
입력 영상은 사용자가 가지고 있는 로컬 MP4이며 권장 경로는 input/badapple.mp4다.
없는 파일이나 도구는 확인한 범위만 차단 사유로 남기고, 독립적으로 가능한 구현은 진행하라.
먼저 소규모 실제 데이터 연결을 확인하고, P2의 1만 후보 수집과 P3의 10초 평가 결과를
만들어라. 10만·100만 후보로 바로 확대하거나 포토모자이크로 방향을 바꾸지 마라.
실제 실행한 검증과 미검증을 구분하고 PLAN의 현재 상태·다음 작업을 갱신하라.
```

이 ZIP에는 `src/`, `tests/`, 의존성 파일, 프로젝트용 스크립트를 만들지 않았다. 그런 파일은 구현을 시작하는 시점에 실제 필요에 맞게 추가한다. 원문에 있는 샘플 코드도 구현 완료물이나 실행 검증 결과가 아니다.

## 라이선스와 출처

프로젝트 자체의 배포 라이선스는 아직 정하지 않았다. 사용한 개발 템플릿의 출처와 고정 커밋은 구성 이력에 기록했다. 위성·항공사진의 이용 조건, 원본 영상과 음악의 권리는 서로 별개이며, 자세한 출처·고지 규칙은 [TECH](docs/TECH.md#10-출처권리비용-경계)에서 관리한다. 이 ZIP에는 원본 영상·음원·위성사진이 포함되지 않는다.
