# Bad Apple Earth — 개발 계획

## 현재 상태

<!-- 진행 단계, 목표 일정·가용 시간, 장애와 남은 확인 사항을 간결하게 유지한다. -->

- **현재 단계:** P4의 10만 후보 수집·동일 타깃 비교 완료. 다음은 P5의 100만 규모 증분 확대다. 실제 영상 재생 평가는 별도로 남아 있다.
- **목표 일정·가용 시간:** 별도 일정·작업 시간·최종 해상도·전곡 완성 기한은 정하지 않았다.
- **확인된 구현·검증:** uv CLI의 입력 검사·목표 추출·수집·MSE 검색·사진 캐시·무음 렌더와 증분 인덱스 결합을 구현했다. 실제 10만 장소·40만 회전 view에서 목표 60개의 Top-20, 평가 목표 20개의 Top-5, 컬러·흑백·비교 MP4를 생성했다. 1만 회전 기준 대비 평균 Best MSE가 22.38% 감소했고 58개 목표 개선·2개 동률이다. 기존 1만·0도 결과도 보존한다. 상세 근거는 [P4 기록](history/2026-11-01-P4-expansion.md)에 둔다.
- **입력:** `input/badapple.mp4`가 로컬에 있고 Git에서 제외된다. 1444×1080, 30000/1001fps, 약 232.13초, H.264/AAC 스테레오다. 전체 프레임 보존·38초부터 10초 구간을 `config/targets.json`에 고정했고 실제 PTS로 목표 60개를 추출했다. 오디오 사용권은 미확인이다.
- **외부 확인:** `data/index/p4-100k/`는 기존 `p2-10k`와 신규 `p4-additional-90k`를 참조하며, 총 72개 AOI·6개 지형군·205개 실제 장면의 고유 tile 100,000개다. 신규 수집의 블록 경계 관측 RSS 최대 약 524MiB, 관측 디스크 약 4.97GiB다. 정상 수신한 자료의 확인용 재다운로드는 하지 않았고, 과도한 결측 제외 오류를 조사할 때 실제 창 한 개만 다시 읽었다. NAIP 읽기는 수행하지 않았다.
- **주요 미검증:** 실제 재생에 의한 움직임 인식성, 100만 및 이후 규모의 표현력, 원본 오디오 경로, 원본 MP4의 회전 메타데이터·비정사각 픽셀 입력. 위성 사진의 직각 회전은 검색·출력에 구현했다. P4의 지역·스케일 분포와 결측 처리 정책도 달라져 점수 감소를 순수한 수량 효과로 분리하지 않았다. Top-5 정지 비교만 확인했으며 기술적 출력 성공을 작품 품질 성공으로 판단하지 않는다.

소규모 실험의 주목적은 기술적 동작과 비용·오류를 확인하는 것이다. 데이터셋은 가용 자원·접근 조건 안에서 최대한 넓고 다양하게 구축하며, 1만·10만·100만은 중간 비교 지점이다. 작은 표본에서 그럴싸한 결과가 나와야만 확대할 수 있는 것은 아니다.

이 문서의 단계 ID는 현재 하네스의 P1–P6이다. 과거 명세의 P0–P4와 번호가 다르며, 과거 표의 진행 상태나 완료 표시를 가져오지 않는다. 각 단계의 현재 설명과 관련 F/N을 기준으로 작업한다.

### P1. 실행 기반·실제 데이터 접근·입력 확인

- **목표:** 구현 환경을 정하고 실제 지리 영상을 소량 읽으며, 제공된 MP4의 입력 계약을 확인한다.
- **관련 요구사항:** F1, F2, F7, F11, N1–N7.
- **선행 조건:** 이 문서와 SPEC/TECH 검토. MP4는 입력 검증에만 필요하고 데이터 소스 검증의 선행 조건은 아니다.
- **상태:** 완료.
- **주요 작업:**
  - [x] OS·Python·FFmpeg·RAM·디스크·네트워크 환경을 확인하고 실제 지원 범위를 기록한다.
  - [x] uv로 실제 구현에 필요한 최소 Python 패키지·의존성·테스트 구조를 만든다. 선택 기능 의존성은 모두 미리 설치하지 않는다.
  - [x] TECH의 AOI 제안 중 서로 다른 2~3개 지형을 고르고 날짜·quota·접근 정책 설정을 작성한다. 설정 파일은 루트 `config/`에서 추적한다.
  - [x] Sentinel-2 `sentinel-2-c1-l2a`의 실제 item·`visual`·`scl` 계약을 확인하고 작은 COG window를 읽는다.
  - [x] 100~500 후보 상한 안에서 실제 RGB·유효 mask·좌표·촬영 시점·window를 확인한다. AOI 밖 장면 중앙만 읽고 AOI 수집에 성공했다고 하지 않는다.
  - [x] 같은 창 재추출, 좌표 중심/footprint·CRS 순서·픽셀 형식 테스트를 작성한다. 네트워크 테스트는 명시적 별도 경로로 둔다.
  - [x] MP4가 있으면 ffprobe·대표 프레임으로 콘텐츠 비율과 10초 구간을 확정한다. 없으면 F1 입력 검증만 차단으로 표시한다.
  - [x] 실제 동작한 환경 준비·접근 방법만 README에 반영한다. NAIP는 이 단계에서 과금·asset 정책을 검토할 수 있으나 대량 읽지 않는다.
- **완료 기준:** 실제 COG에서 얻은 사진과 출처/좌표/창을 재확인할 수 있고, 환경/의존성/접근 조건을 명시한다. MP4가 제공된 경우 probe·구간·비율도 확인한다. 미제공이면 해당 부분 완료를 주장하지 않는다.
- **검증·완료 근거:** Windows 11·uv 0.13.6·Python 3.12.16, 실제 후보 120개, 오프라인 테스트 12개 통과, 대표 재추출 12개 일치. [P1 기록](history/2026-11-01-P1-access.md), 로컬 `data/p1-sample-v2/`와 `data/p1-input/`. 정상 다운로드의 반복 확인은 추가하지 않는다.

### P2. 재개 가능한 1만 후보 수집기·인덱스

- **목표:** 다양한 지역·스케일의 실제 후보를 한 번 모으고 중단 후 재사용할 수 있게 한다.
- **관련 요구사항:** F2, F3, F4, F5, F10, F11, N1–N7.
- **선행 조건:** P1의 환경·Sentinel 실제 접근 확인. 원본 MP4의 입력 검증이 아직 차단이어도 기본 비율 가정을 명시한 별도 인덱스 실험은 가능하다. 실제 타깃 비율이 달라지면 호환성을 확인한다.
- **상태:** 완료.
- **주요 작업:**
  - [x] AOI·지형군·장면·스케일별 quota와 전역 window 생성 규칙을 구현한다.
  - [x] 3개 초기 스케일, stride, COG 블록+halo 읽기를 구현한다.
  - [x] 유효 mask·SCL 정렬·품질 태그·정확/근접 중복을 처리한다. 단색 정상 지형은 보존한다.
  - [x] 공통 coarse/fine 특징과 출처를 불변 shard로 저장하고 행 매핑·버전·checksum을 관리한다.
  - [x] 작업 상태·제한된 재시도·자원 한도·staging commit·crash 복구를 구현한다.
  - [x] 오프라인 배치에서 재실행·중단·복구를 확인한 뒤 실제 1만 유효 후보까지 수집한다.
  - [x] 실제 후보의 결정적 무작위 200장 contact sheet와 지형/스케일/품질/오류 통계를 생성한다.
- **완료 기준:** 1만 규모 인덱스의 행 수·출처·특징이 맞고 중단/재시작해 중복이 늘지 않는다. 지형 다양성과 잘못된 검은/흰 후보를 실제 이미지로 검토한다. quota 미달 시 실제 수와 이유를 명시한다.
- **검증·완료 근거:** 수집 계약 테스트 4개와 실제 수집·캐시 재개. 후보 10,000개, 지형군별 1,666–1,667개, 폭 256/512/1024px별 5,425/3,265/1,310개다. 블록 경계 관측 RSS 최대 약 302MiB, 관측 디스크 약 1.68GB이며 요청/수신 바이트는 미계측이다. `data/index/p2-10k/manifest.json`, `contact-sheet.jpg`, [P2–P3 기록](history/2026-11-01-P2-P3-pipeline.md)에 근거를 둔다. 무작위 시트 전체를 별도 검수하지 않고 P3의 Top-5 비교만 확인했다.

### P3. 1만 후보로 Top-K·10초 기술 검증과 기준 결과

- **목표:** “한 프레임 = 실제 장소 한 장”의 검색·재추출·렌더가 정확히 연결되는지 검증하고 확대 비교용 기준 결과를 만든다. 이 규모에서 작품의 표현력을 충분히 판단할 수 있다고 가정하지 않는다.
- **관련 요구사항:** F1, F5, F6, F7, F8, F9, F11, N1–N7.
- **선행 조건:** P2의 유효 후보 인덱스, 실제 MP4, FFmpeg. MP4가 없다면 입력 독립 검색 테스트·렌더 단위 구현은 진행하되 실제 결과는 차단한다.
- **상태:** 기술 기준 결과 생성 완료. 실제 재생에 의한 시각 평가는 미실시.
- **주요 작업:**
  - [x] 고정 구간 10초·6fps 목표 60개와 평가 프레임 20개를 준비한다.
  - [x] 정확한 MSE 배치 검색과 안정적인 Top-K·동률 처리를 구현한다. coarse 픽셀은 int32 SSE를 MSE로 환산한다.
  - [x] 타깃 20개에 대해 Top-5 비교 자료와 기준선 점수를 만든다.
  - [x] 기존 표본·블록 캐시를 우선 사용해 선택 사진과 cache·manifest를 만든다. 캐시에 없는 사진만 실제 COG에서 읽고 실패/대체 사유를 남긴다.
  - [x] 컬러 10초 MP4를 24fps hold로 렌더한다. 흑백·원본과 나란히 보기 등 평가 자료를 만든다.
  - [x] 권리 미확인 상태에 맞춰 명시적 무음 모드로 출력한다. 원본 오디오 동기화는 후속 구현이다.
  - [ ] 실제 재생과 출처 샘플 확인으로 성공 구간·실패 구간·미검증을 평가한다.
- **완료 기준:** 실제 데이터만 사용한 MP4·Top-5·출처 목록을 재현할 수 있다. **기술적 출력 완료와 해당 표본의 시각 관측을 별도로 기록한다.** 형태가 보이지 않아도 정확성 검증과 다음 확대의 자원·접근 계획이 있으면 다음 단계로 진행한다. 작은 표본의 낮은 인식성만으로 방식의 실패를 판정하지 않는다.
- **검증·완료 근거:** `data/runs/p3-10k/`의 `color.mp4`, `gray.mp4`, `comparison.mp4`, `top5.jpg`, `matches.parquet`, `selected.parquet`, `manifest.json`. 선택은 60개 슬롯·26개 실제 사진이며 대체/재추출 실패는 없다. Best MSE 평균 약 0.07291, 중앙값 약 0.06903이다. 컬러 출력 메타데이터는 H.264 256×192, 24fps, 240프레임, 10.000초다. Top-5 정지 비교만 확인했고 실제 재생 평가는 미실시다. [P2–P3 기록](history/2026-11-01-P2-P3-pipeline.md)에 고정 ID와 한계를 둔다.

### P4. 동일 타깃의 10만 후보 비교와 병목 개선

- **목표:** 추가 수집이 실제 품질 개선에 도움이 되는지 측정하고 필요한 병목만 개선한다.
- **관련 요구사항:** F2–F11, F13, N1–N7.
- **선행 조건:** P3의 기술적 동작·비용 검토. 구현/마스크/명암 오류가 있으면 먼저 고친다. P3의 시각적 성공은 선행 조건이 아니다.
- **상태:** 수집·기술 비교 완료. `data/index/p4-additional-90k/`의 실제 90,000개와 기존 10,000개를 결합한 `data/index/p4-100k/`가 있다. 실제 재생 평가는 미실시다.
- **주요 작업:** 고정된 target set과 metric을 유지한 채 부족한 지역·스케일을 중심으로 최대 10만 후보까지 확장한다. raw MSE·시각 품질·반복률·RAM·디스크·실행비용을 비교한다. 필요가 입증된 경우에만 정확 FAISS 검색 등을 검토한다.
- **완료 기준:** 1만 대 10만의 동등 조건 비교와 확장/중단 근거가 남는다. 후보 집합·필터·metric이 바뀌었다면 규모 효과와 알고리즘 효과를 구분한다.
- **완료 근거:** 수집 중 회전 특징 저장, 참조 bundle, 중복 제외, 멤버별 사진 캐시, 동일 조건 비교를 실제 실행했다. 결과는 `data/runs/p4-100k/`다. 평균 Best MSE는 0.06719→0.05216, 선택은 25개 장소·29개 view다. 핵심 계약 테스트 8개·부족분 재배분 1개·RGB 결측 수정 1개가 통과했다. 초기 해안·산악 부족분은 같은 지형군에서 채웠다. RGB 채널 중 하나가 0인 유효 픽셀을 잘못 제외하던 오류도 수정했으므로 개선은 지역·분포·정책 변화가 함께 반영된 결과다. [P4 기록](history/2026-11-01-P4-expansion.md)에 설정·ID·자원·관측·한계를 둔다.

### P5. 대규모 데이터셋 확대와 필요 기반 소스·검색 보강

- **목표:** 닮은 장면을 찾을 기회를 넓히도록 가용 범위에서 데이터셋을 최대한 확대하고, 필요한 소스·검색 보강을 비교한다.
- **관련 요구사항:** F2–F7, F9–F13, N1–N7.
- **선행 조건:** 수집·검색의 정확성, P4 자원 계측과 외부 접근 조건 확인. 소규모에서의 시각 품질 개선은 필수 선행 조건이 아니다. 보강 알고리즘은 해결할 문제를 특정한 뒤 추가한다.
- **상태:** 직각 회전과 10만 규모 비교 완료. 다음 실행은 100만 규모를 향한 지역·스케일 확대이며 나머지 보강은 대기한다.
- **주요 작업:** 지역·지형·지상 스케일을 넓히며 100만 및 이후 규모를 실행별 자원 한도 안에서 구축한다. 0/90/180/270도 view를 기본 검색에 포함하며 각도 고정 기준선도 보존한다. 필요에 따라 NAIP 접근·밴드·비용 검증, 직각 외 각도, fine/edge/SSIM 재정렬, 약한 반복 페널티를 **한 변경씩** 비교한다. 유료 접근·대규모 클라우드는 별도 승인 조건을 유지한다.
- **완료 기준:** 중간 규모별 동일 타깃 비교·실제 출력·비용이 남고 도달 규모와 자원·접근상의 상한 또는 충분한 탐색 근거를 기록한다. 회전과 실제 출력의 비율/화각 일치, NAIP의 실제 접근 조건을 검증한다. 선택 보강의 채택·보류와 데이터셋 확대 판단을 구분한다.
- **검증·완료 근거:** 직각 회전은 `data/runs/p3-10k-rotations/`에 실행했다. 같은 1만 장소의 4만 view를 검색했고 평균 Best MSE는 0도 약 0.07291에서 약 0.06719로 7.84% 감소했다. 선택은 21개 장소·27개 view이며 60슬롯의 각도별 수는 0/90/180/270도 순서로 10/15/10/25다. 회전·크롭·좌표·검색/출력 일치에 관한 핵심 테스트를 포함해 5개가 통과했다. 이는 회전+크롭 view 확장 효과이며 데이터 규모 효과나 재생 인식성 성공을 뜻하지 않는다. [회전 기록](history/2026-11-01-rotation-views.md)에 범위와 캐시 비용을 남긴다.

### P6. 품질 검증 후 30초·전곡 제작

- **목표:** 검증한 방식으로 긴 결과물과 재현 가능한 제작 자료를 완성한다.
- **관련 요구사항:** F1, F5–F11, F13, N1–N7.
- **선행 조건:** P3/P4 또는 선택한 P5 개선의 시각 품질 확인, 실제 제작 리소스와 원본/데이터 권리 검토. 100만 후보나 NAIP 사용 자체가 필수 선행 조건은 아니다.
- **상태:** 보류.
- **주요 작업:** 30초에서 전체 길이로 확장하며 필요한 매칭 fps·출력 크기를 조정한다. 모든 선택 사진을 캐시하고 오디오/시간축/프레임별 출처를 검증한다. 재실행 가능한 설정·설치·결과 manifest·크레딧을 정리한다.
- **완료 기준:** 실제 재생 가능한 결과·원본 대비 평가·전 프레임 출처·재현 절차가 존재한다. 공개 배포는 별도 결정이며 자동 업로드하지 않는다.
- **검증·완료 근거:** 아직 없음. 최종 run, 검증 환경, 결과·권리 상태와 필요한 인계 자료를 연결한다.
