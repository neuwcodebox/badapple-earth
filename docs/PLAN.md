# Bad Apple Earth — 개발 계획

## 현재 상태

<!-- 진행 단계, 목표 일정·가용 시간, 장애와 남은 확인 사항을 간결하게 유지한다. -->

- **현재 단계:** 하네스 문서 구성 완료. 구현 착수 전이며 P1이 다음 단계다.
- **목표 일정·가용 시간:** 별도 일정·작업 시간·최종 해상도·전곡 완성 기한은 정하지 않았다.
- **확인된 구현·검증:** 애플리케이션 코드·설치 패키지·테스트·수집 데이터·결과 영상은 없다. 문서 구조·상호 링크·ID 연결·원문 보존 검사는 [구성 이력](history/2026-11-01-workspace.md)에 기록한다.
- **입력:** 사용자는 원본 MP4를 가지고 있다. ZIP에는 포함되지 않았고 권장 로컬 경로는 `input/badapple.mp4`다. 파일 속성·내용·오디오 사용권은 아직 확인하지 않았다.
- **외부 확인:** 공식 컬렉션/서비스 문서를 읽어 Sentinel-2·NAIP의 소스 계약을 정리했다. 실제 COG 픽셀 읽기와 수집기는 실행하지 않았다.
- **주요 미검증:** 실행 머신·의존성, 실제 소스 접근, MP4 콘텐츠 비율/테스트 구간, 1장 사진 방식의 표현력, 규모 확대 효과.

이 문서의 단계 ID는 현재 하네스의 P1–P6이다. 과거 명세의 P0–P4와 번호가 다르며, 과거 표의 진행 상태나 완료 표시를 가져오지 않는다. 각 단계의 현재 설명과 관련 F/N을 기준으로 작업한다.

## 개발 단계

### P1. 실행 기반·실제 데이터 접근·입력 확인

- **목표:** 구현 환경을 정하고 실제 지리 영상을 소량 읽으며, 제공된 MP4의 입력 계약을 확인한다.
- **관련 요구사항:** F1, F2, F7, F11, N1–N7.
- **선행 조건:** 이 문서와 SPEC/TECH 검토. MP4는 입력 검증에만 필요하고 데이터 소스 검증의 선행 조건은 아니다.
- **상태:** 예정.
- **주요 작업:**
  - [ ] OS·Python·FFmpeg·RAM·디스크·네트워크 환경을 확인하고 실제 지원 범위를 기록한다.
  - [ ] 실제 구현에 필요한 최소 Python 패키지·의존성·테스트 구조를 만든다. 선택 기능 의존성은 모두 미리 설치하지 않는다.
  - [ ] TECH의 AOI 제안 중 서로 다른 2~3개 지형을 고르고 날짜·quota·접근 정책 설정을 작성한다. 설정 파일은 루트 `config/`에서 추적한다.
  - [ ] Sentinel-2 `sentinel-2-c1-l2a`의 실제 item·`visual`·`scl` 계약을 확인하고 작은 COG window를 읽는다.
  - [ ] 100~500 후보 상한 안에서 실제 RGB·유효 mask·좌표·촬영 시점·window를 확인한다. AOI 밖 장면 중앙만 읽고 AOI 수집에 성공했다고 하지 않는다.
  - [ ] 같은 창 재추출, 좌표 중심/footprint·CRS 순서·픽셀 형식 테스트를 작성한다. 네트워크 테스트는 명시적 별도 경로로 둔다.
  - [ ] MP4가 있으면 ffprobe·대표 프레임으로 콘텐츠 비율과 10초 구간을 확정한다. 없으면 F1 입력 검증만 차단으로 표시한다.
  - [ ] 실제 동작한 환경 준비·접근 방법만 README에 반영한다. NAIP는 이 단계에서 과금·asset 정책을 검토할 수 있으나 대량 읽지 않는다.
- **완료 기준:** 실제 COG에서 얻은 사진과 출처/좌표/창을 재확인할 수 있고, 환경/의존성/접근 조건을 명시한다. MP4가 제공된 경우 probe·구간·비율도 확인한다. 미제공이면 해당 부분 완료를 주장하지 않는다.
- **검증·완료 근거:** 아직 없음. 완료 시 실행 환경·실제 샘플·관련 테스트와 history 경로를 기록한다.

### P2. 재개 가능한 1만 후보 수집기·인덱스

- **목표:** 다양한 지역·스케일의 실제 후보를 한 번 모으고 중단 후 재사용할 수 있게 한다.
- **관련 요구사항:** F2, F3, F4, F5, F10, F11, N1–N7.
- **선행 조건:** P1의 환경·Sentinel 실제 접근 확인. 원본 MP4의 입력 검증이 아직 차단이어도 기본 비율 가정을 명시한 별도 인덱스 실험은 가능하다. 실제 타깃 비율이 달라지면 호환성을 확인한다.
- **상태:** 예정.
- **주요 작업:**
  - [ ] AOI·지형군·장면·스케일별 quota와 전역 window 생성 규칙을 구현한다.
  - [ ] 3개 초기 스케일, stride, COG 블록+halo 읽기를 구현한다.
  - [ ] 유효 mask·SCL 정렬·품질 태그·정확/근접 중복을 처리한다. 단색 정상 지형은 보존한다.
  - [ ] 공통 coarse/fine 특징과 출처를 불변 shard로 저장하고 행 매핑·버전·checksum을 검사한다.
  - [ ] 작업 상태·제한된 재시도·자원 한도·staging commit·crash 복구를 구현한다.
  - [ ] 먼저 작은 배치에서 재실행·중단·복구를 시험한 뒤 최대 1만 유효 후보까지 수집한다.
  - [ ] 실제 후보의 무작위 100~200장 contact sheet와 지형/스케일/품질/오류 통계를 생성한다.
- **완료 기준:** 1만 규모 인덱스의 행 수·출처·특징이 맞고 중단/재시작해 중복이 늘지 않는다. 지형 다양성과 잘못된 검은/흰 후보를 실제 이미지로 검토한다. quota 미달 시 실제 수와 이유를 명시한다.
- **검증·완료 근거:** 아직 없음. 테스트 결과·선택 catalog/index ID·contact sheet·자원 실측·복구 결과를 연결한다.

### P3. 1만 후보로 Top-K·10초 결과·시각 평가

- **목표:** “한 프레임 = 실제 장소 한 장”으로 원본 형상 변화가 보이는지 판단할 최초 결과를 만든다.
- **관련 요구사항:** F1, F5, F6, F7, F8, F9, F11, N1–N7.
- **선행 조건:** P2의 유효 후보 인덱스, 실제 MP4, FFmpeg. MP4가 없다면 입력 독립 검색 테스트·렌더 단위 구현은 진행하되 실제 결과는 차단한다.
- **상태:** 예정.
- **주요 작업:**
  - [ ] 고정 구간 10초·6fps 목표 60개와 평가 프레임 20개를 준비한다.
  - [ ] float32 MSE 배치 정확 검색과 안정적인 Top-K·동률 처리를 구현한다.
  - [ ] 타깃 20개에 대해 Top-5 비교 자료와 기준선 점수를 만든다.
  - [ ] 선택 후보를 실제 COG에서 재추출하고 cache·manifest를 만든다. 실패/대체 사유를 남긴다.
  - [ ] 컬러 10초 MP4를 24fps hold로 렌더한다. 흑백·원본과 나란히 보기 등 평가 자료를 만든다.
  - [ ] 오디오 트랙과 권리 상태에 맞춰 동기화 또는 명시적 무음 모드를 검증한다.
  - [ ] 실제 재생과 출처 샘플 확인으로 성공 구간·실패 구간·미검증을 평가한다.
- **완료 기준:** 실제 데이터만 사용한 MP4·Top-5·출처 목록을 재현할 수 있다. **기술적 출력 완료와 작품 인식성 평가를 별도로 기록한다.** 형태가 안 보이더라도 그 사실과 다음 실험 근거가 있으면 실험 단계는 종료할 수 있다.
- **검증·완료 근거:** 아직 없음. 결과 경로, run/index/target ID, 수치와 실제 시각 평가 여부를 기록한다.

### P4. 동일 타깃의 10만 후보 비교와 병목 개선

- **목표:** 추가 수집이 실제 품질 개선에 도움이 되는지 측정하고 필요한 병목만 개선한다.
- **관련 요구사항:** F2–F11, F13, N1–N7.
- **선행 조건:** P3의 재생·Top-K 결과 검토. 구현/마스크/명암 오류가 있으면 먼저 고친다. 근거 없이 후보 수부터 늘리지 않는다.
- **상태:** 예정. P3 결과에 따라 범위 조정 또는 보류할 수 있다.
- **주요 작업:** 고정된 target set과 metric을 유지한 채 부족한 지역·스케일을 중심으로 최대 10만 후보까지 확장한다. raw MSE·시각 품질·반복률·RAM·디스크·실행비용을 비교한다. 필요가 입증된 경우에만 정확 FAISS 검색 등을 검토한다.
- **완료 기준:** 1만 대 10만의 동등 조건 비교와 확장/중단 근거가 남는다. 후보 집합·필터·metric이 바뀌었다면 규모 효과와 알고리즘 효과를 구분한다.
- **검증·완료 근거:** 아직 없음. 비교 run ID와 품질·자원 리포트, 채택/보류 근거를 연결한다.

### P5. 조건부 소스·검색 보강 및 최대 100만 후보

- **목표:** P3/P4에서 드러난 특정 실패 패턴을 실제로 개선한다.
- **관련 요구사항:** F2–F7, F9–F13, N1–N7.
- **선행 조건:** P4 비교 근거 또는 P3에서 명확히 드러난 소스/스케일 한계. 자원 한도와 외부 접근 조건 확인.
- **상태:** 보류.
- **주요 작업:** 필요에 따라 NAIP 접근·밴드·비용 검증, 다른 지상 스케일, 90/180/270도 view, fine/edge/SSIM 재정렬, 약한 반복 페널티를 **한 변경씩** 비교한다. 유효한 개선이 확인되고 예산이 허용할 때만 최대 100만까지 확장한다.
- **완료 기준:** 개선 전후 동일 타깃 비교·실제 출력·비용 차이·채택 여부가 남는다. 회전과 실제 출력의 비율/화각 일치, NAIP의 실제 접근 조건을 검증한다. 도움이 안 되면 중단 근거를 남기고 완료 처리할 수 있다.
- **검증·완료 근거:** 아직 없음. 개선 실험별 run과 관련 테스트·정책 확인을 연결한다.

### P6. 품질 검증 후 30초·전곡 제작

- **목표:** 검증한 방식으로 긴 결과물과 재현 가능한 제작 자료를 완성한다.
- **관련 요구사항:** F1, F5–F11, F13, N1–N7.
- **선행 조건:** P3/P4 또는 선택한 P5 개선의 시각 품질 확인, 실제 제작 리소스와 원본/데이터 권리 검토. 100만 후보나 NAIP 사용 자체가 필수 선행 조건은 아니다.
- **상태:** 보류.
- **주요 작업:** 30초에서 전체 길이로 확장하며 필요한 매칭 fps·출력 크기를 조정한다. 모든 선택 사진을 캐시하고 오디오/시간축/프레임별 출처를 검증한다. 재실행 가능한 설정·설치·결과 manifest·크레딧을 정리한다.
- **완료 기준:** 실제 재생 가능한 결과·원본 대비 평가·전 프레임 출처·재현 절차가 존재한다. 공개 배포는 별도 결정이며 자동 업로드하지 않는다.
- **검증·완료 근거:** 아직 없음. 최종 run, 검증 환경, 결과·권리 상태와 필요한 인계 자료를 연결한다.

### NAIP·회전·고급 재정렬·100만 후보

- **관련 요구·단계:** F12, F13, P5.
- **보류 이유:** 기준선의 약점·추가 소스 비용·자원 효과를 아직 측정하지 않았다.
- **재개 조건:** P3/P4에서 해결할 문제가 구체화되고 개선 실험 조건/비용을 확인한다. 과금이 있으면 먼저 사용자 승인을 받는다.

### 30초·전곡·고해상도·높은 매칭 fps

- **관련 요구·단계:** F13, P6.
- **보류 이유:** 짧은 결과의 실제 표현력이 먼저다.
- **재개 조건:** 재생 품질과 자원·권리 조건을 통과한다. 1만/10만에서 충분히 잘 되면 100만을 억지로 거치지 않는다.

### 포토모자이크와 추가 연출·UI

- **관련 요구·단계:** N1의 기본 콘셉트 제약. 현재 필수 단계에는 배정하지 않는다.
- **보류 이유:** 포토모자이크는 별도 작품 방식이며, 지도 UI·가상 카메라 이동·대륙별 서사·실사 복원·생성형 영상은 현재 목표가 아니다.
