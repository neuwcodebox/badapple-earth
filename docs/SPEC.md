# Bad Apple Earth — 요구사항

## 배경과 목표

### 해결할 문제

Bad Apple!! 영상을 다른 화풍으로 변환하는 대신, **지구에 실제로 존재하는 장소의 위성·항공사진 중 각 프레임과 가장 닮은 한 장을 찾는다.** 정지화면은 자연스러운 지리 사진이고, 이어서 재생하면 사진들의 큰 명암 배치 속에서 원본 움직임이 드러나는 작품을 목표로 한다.

이 프로젝트의 핵심 불확실성은 실제 사진에 충분히 닮은 패턴이 존재하는지다. 닮은 장면을 찾을 기회를 넓히기 위해 데이터셋은 가용 자원·접근 조건 안에서 최대한 크고 다양하게 구축한다. 소규모 후보는 기술적 동작을 검증하기 위한 표본이며 표현력을 판단하기에는 부족할 수 있다. 다운로드·검색 프로그램이 실행된다는 사실과 작품이 재미있고 알아볼 만하다는 사실을 분리해서 검증해야 한다.

### 목표

개발자/창작자가 보유한 로컬 MP4를 입력하고, 실제 촬영 데이터의 수집·전처리·검색·재추출·영상 출력을 반복할 수 있게 한다. 데이터셋을 재사용하고, 수집량을 늘렸을 때 품질이 실제 개선되는지 판단할 수 있어야 한다.

### 완성된 모습

최종 제작물은 보유 MP4의 전체 프레임을 사용한 전곡 영상이다. 16:9 화면에서 작은 원본, 세로로 배치한 Top-K 장소 사진, 최종 선택을 강조하는 연결선, 큰 변환 영상을 함께 보여준다. 큰 영상 아래에 실제 이미지 메타데이터 한 줄을 표시한다. 실제 장소 사진만 나오는 영상과 프레임별 위치·촬영 시점·원본 자산·변환 기록도 보존한다.

## 사용자와 핵심 사용 흐름

### 보유 영상으로 첫 결과 만들기

- **사용자·상황:** 원본 Bad Apple MP4를 가진 창작자가 실제 지구 사진으로 새로운 표현을 시험한다.
- **흐름:** MP4 지정 → 콘텐츠 비율·구간 확인 → 소규모 데이터 연결 → 1만 후보 수집 → Top-K 검색 → 실제 사진 재추출 → 10초 재생·비교 평가.
- **관련 요구사항:** F1–F9, F11, N1–N6.

### 데이터셋을 재사용하며 개선하기

- **사용자·상황:** 첫 결과가 기대보다 부족하거나 후보가 특정 지형에 편중되어 있다.
- **흐름:** 실패 프레임 분석 → 지역·스케일·특징을 한 요인씩 조정 → 중단된 수집 재개 → 동일 목표 프레임 재검색 → 전후 점수와 영상 비교 → 확장 또는 중단 근거 기록.
- **관련 요구사항:** F3–F7, F9–F13, N2–N7.

## 범위

<!-- 첫 실사용과 후속 목표를 구분하고, 의도적으로 제외한 범위를 명시한다. -->

### 제작 범위

F1–F11, F12의 직각 회전과 F14의 설명 화면을 묶어 로컬 제작 흐름을 완성한다. Sentinel-2와 grayscale MSE CPU 전수 검색을 기본으로 사용한다. 사진 방향은 0·90·180·270도이며 실제 출력에도 선택한 회전과 비율 유지 크롭을 적용한다. 최종본은 입력 전체를 디코드해 원본 프레임마다 결과를 하나씩 만들고 원래 프레임 순서·PTS 간격을 유지한다. 검색 계산의 중복 제거가 출력 프레임 생략으로 이어져서는 안 된다.

10초·6fps 매칭·24fps hold는 규모와 방법을 비교하는 기술 실험 설정이다. 1만·10만·100만은 최종 상한이 아니라 기술·자원·품질을 기록하는 중간 지점이며 작은 표본의 시각 품질만으로 확대를 중단하지 않는다. 최종본의 모든 프레임 사용 조건은 이 실험 설정과 구분한다.

### 후속 범위

F12의 NAIP·직각 외 회전·재정렬은 필요가 확인된 경우에 추가한다. F13의 데이터셋 확대는 기술적 정확성·자원·접근 조건을 확인해 진행한다. 웹 서비스와 지도 UI는 현재 제작에 필요하지 않다.

### 제외 범위

생성형 AI 이미지, 원본 실루엣 덧씌우기, 지형을 임의로 칠하기, 여러 장소를 기본 프레임으로 합성하기, Google Maps/Earth 무단 대량 스크래핑, MP4 재다운로드, LLM 서비스, 상시 서버, 캐릭터·카메라 연속성, 기본 모드의 프레임 보간·모핑·crossfade는 제외한다.

포토모자이크는 “한 프레임이 한 실제 장소”라는 목표와 다르다. A 방식이 부족하더라도 임의의 해결책으로 전환하지 않는다. 추후 별도 요청 시 별도 모드·결과물로 정의하며 A의 성과를 덮어쓰지 않는다.

## 기능 요구사항

<!-- 각 기능의 동작과 외부에서 확인할 수 있는 수용 기준을 기록한다. -->

### F1. 로컬 MP4 분석과 목표 프레임 준비

- **목적:** 사용자가 이미 가진 영상으로 정확한 비교 기준을 만든다.
- **기대 동작과 경계:** 전체 프레임 모드와 기술 실험용 구간 샘플링 모드를 제공한다. 해상도·길이·영상/오디오 스트림·종횡비·타임스탬프를 확인하고 콘텐츠 영역을 확정한다. 원본을 수정하지 않는다.
- **수용 기준:**
  - 파일과 구간이 유효하면 시간정보가 있는 목표 프레임과 입력 식별 기록을 만든다. 10초·6fps 설정에서는 60개의 목표 시점이 생성된다.
  - 최종 제작에서는 실제 디코드 프레임을 하나도 건너뛰지 않고 각 프레임의 PTS·time base·순서를 남긴다. 지원하지 않는 시간축을 임의로 재샘플링하지 않는다.
  - 고정 4:3으로 찌그러뜨리지 않으며 여백 제거 결정이 저장된다. 검은 실루엣을 여백으로 오인해 프레임별 자동 크롭하지 않는다.
  - 파일 누락·손상·범위 초과는 구체적인 오류로 끝난다. 오디오가 없는 입력도 무음 경로로 처리한다.

### F2. 실제 촬영 장면 검색과 접근 검증

- **목적:** 실제 출처와 읽기 조건이 확인된 영상만 수집 대상으로 삼는다.
- **기대 동작과 경계:** 소스별 STAC 카탈로그에서 AOI·시기·품질·할당량으로 검색한다. 컬렉션/자산/밴드/인증·비용 조건을 확인하고 장면 목록을 고정한다.
- **수용 기준:**
  - 페이지네이션과 검색 한도를 구분하고 후보 수·선택 이유·제외 사유가 남는다.
  - 자산을 찾지 못하거나 접근이 거부되면 실패 소스를 식별한다. API 목록 조회 성공을 영상 픽셀 읽기 성공으로 표시하지 않는다.
  - Sentinel-2 필터를 NAIP에 그대로 적용하지 않는다. 유료 접근은 자동 활성화하지 않는다.

### F3. AOI 기반 다중 스케일 수집

- **목적:** 지역과 관측 범위가 다양한 명암·형태 후보를 만든다.
- **기대 동작과 경계:** 장면을 블록 단위로 읽고 여러 크기의 연속된 지리 영역을 추출한다. 지역·지형군·장면·스케일별 quota와 원본 비율을 반영한다.
- **수용 기준:**
  - 각 후보에 실제 원본 창, 지상 범위와 AOI가 기록되며 설정한 quota를 넘는 무제한 수집이 발생하지 않는다.
  - 서로 다른 지형군과 스케일의 후보가 확인된다. 동일 지형 인접 창만 늘린 수량을 다양성으로 보고하지 않는다.
  - 블록 경계·장면 경계에서 누락·이중 집계·다른 장면 접합이 없음을 확인할 수 있다.

### F4. 품질 검사와 중복 관리

- **목적:** NoData·구름·손상 이미지가 좋은 매칭으로 선택되는 것을 방지한다.
- **기대 동작과 경계:** 유효 마스크, 로컬 구름, 픽셀 형식, 저분산, 인접 중복을 검사한다. SCL 사용 가능 여부와 추정 품질을 구분한다.
- **수용 기준:**
  - 명확한 손상·결측·과다 구름 후보는 검색/출력에서 제외되고 이유가 남는다.
  - 바다·사막·눈 등 유효한 저분산 지형은 일괄 삭제하지 않는다.
  - 같은 창 재수집은 중복 ID를 만들지 않으며, 유사 중복 제거로 원본 출처 정보가 사라지지 않는다.

### F5. 재사용 가능한 특징량·메타데이터 저장

- **목적:** 컬러 사진 전체를 메모리나 개별 파일로 쌓지 않고 반복 검색한다.
- **기대 동작과 경계:** 타깃·후보에 공통 전처리를 적용하고 연속값 명암 특징, 필요 보조 특징, 위치·출처·설정 버전과 인덱스 행 매핑을 저장한다.
- **수용 기준:**
  - 프로세스를 다시 시작해 같은 인덱스를 불러오면 동일한 타일을 찾는다.
  - 이진화 표현만 저장하지 않으며 원본 명암과 향상된 특징을 구분한다.
  - 인덱스의 행 수·형상·ID 매핑이 맞지 않으면 잘못된 검색을 계속하지 않고 복구/재생성을 요구한다.

### F6. 형태 중심 Top-K 검색

- **목적:** 의미가 아니라 큰 명암 구조가 닮은 실제 후보를 찾는다.
- **기대 동작과 경계:** 기본 제작은 32×24 grayscale MSE 전수 검색의 Top-20에서 Astra가 원본·원색 후보·앞선 장면과 선택을 고려해 한 장을 고른다. 장소·회전 중복을 먼저 제거해 후보를 줄이지 않는다. 연속 구간을 최대 25개 서브에이전트에 병렬 배정하고 앞 10프레임을 참고로 제공한다. 프레임별 모델 선택과 출처를 보관하며 모델 판단을 수치 점수로 꾸미지 않는다. 화면의 MS-SSIM은 같은 후보에서 얻은 참고값이다. MS-SSIM 최대·직접 MSE 선택도 비교용으로 보존한다. 최종 선택 뒤에 실제 선택과 다른 네 장소를 표시한다. 저장 Top-K의 다섯 지표 재평가·독립 상관 검색·[형태 검색](SHAPE_MATCHING.md)은 별도 비교다. 같은 구간의 모든 원본 프레임을 사용하며 후보 범위와 선택 방법의 효과를 구분한다.
- **방향 검색:** 기본은 시계 방향 0·90·180·270도이며 0도 기준선도 별도로 실행할 수 있다. 실제 장소 수와 회전 view 수를 구분한다.
- **격자·후보 폭 비교:** MSE 16×12와 32×24의 전수 검색을 Top-20·확대 Top-K에서 비교하고 두 격자의 합집합도 평가한다. 최종 MS-SSIM의 해상도·계산식은 고정해 검색 격자와 후보 수의 효과를 분리한다. 기존 RGB·명암 특징과 버전이 같은 평가 점수를 재사용하며 실제 프레임·출처를 보존한다.
- **모델 선택 계약:** 프레임 독립 비교는 에이전트별 배정·제시 순서를 무작위로 섞는다. 채택한 연속 선택은 형태 대응이 비슷할 때 이전 선택과 시각적 연속성을 고려하되 실제 원본 변화에는 따라간다. 후보 순서는 섞고 같은 exact view에는 고정 ID를 표시한다. 기존 순위·점수·선택은 가리고 실제 source PTS·view·무작위 seed와 응답을 연결해 모든 대상 프레임을 원래 순서로 출력한다. 참고 맥락만으로 병렬 구간 경계의 실제 선택 일치가 보장되지는 않는다.
- **수용 기준:**
  - 작은 후보 세트에서 알려진 정답 순서와 일치하고, 동일 입력·동률 규칙에서 순서가 안정적이다.
  - 후보가 K보다 적으면 실제 후보만 반환한다. 후보가 없거나 차원이 다르면 명확히 실패한다.
  - 상위 후보를 재선택할 수 있으며 약한 매칭도 숨기지 않는다. 무작위 선택이나 지역 다양성을 위해 유사도를 현저히 희생하지 않는다.
  - 형태 실험에서는 채워진 영역·구멍·극성·위치와 방향을 함께 평가하고 항목별 최적 마스크를 섞지 않는다. 단색·회색·저시인성 분기와 후보 절단을 명시한다.
  - 선택 사진의 원래 색상·광도를 유지한다. 분석용 이진 마스크나 거리장을 본편에 합성하지 않는다.

### F7. 선택 사진 재추출과 원본 추적

- **목적:** 검색된 후보가 실제 영상 프레임과 동일한 장소·화각임을 보장한다.
- **기대 동작과 경계:** 저장한 품질 판정·원본 식별자·추출 창·변환과 컬러 캐시의 연결을 유지한다. 큰 표시 해상도에 필요한 원본 픽셀만 추가로 읽는다. 정상 수신 확인을 위한 반복 다운로드는 하지 않는다.
- **수용 기준:**
  - 임의의 출력 프레임에서 원본 자산, 촬영 시각, 위치, 추출 창, 실제 변환을 찾아 다시 확인할 수 있다.
  - 캐시만으로 해당 결과를 다시 렌더링할 수 있다. 일시 서명 URL 만료는 식별자를 통해 갱신한다.
  - 실패 후보를 대체하면 대체 순위와 이유를 기록한다. 검은 임시 이미지로 실패를 숨기지 않는다.

### F8. 단일 실제 장소 프레임의 MP4 렌더링

- **목적:** 실제 사진들로만 원본의 시간적 형태 변화를 보여준다.
- **기대 동작과 경계:** 최종본은 원본 프레임마다 실제 사진 한 장을 배정한다. 사용자 제공 오디오를 로컬 결과에 보존하는 모드와 명시적 무음 모드를 제공한다.
- **수용 기준:**
  - 10초·6fps 매칭을 24fps로 출력하면 각 사진을 4프레임씩 유지하며 목표 길이가 맞는다. 다른 fps 조합도 시간 기준으로 처리한다.
  - 전곡 제작의 입력·출력 영상 프레임 수가 일치하며 프레임 누락·복제·보간 없이 원본 순서와 시간축이 유지된다.
  - 원본 컬러/지형을 유지한다. 검색용 명암 정규화·실루엣 마스크를 몰래 출력에 적용하지 않는다.
  - 원본 오디오의 시작점이 맞고 없는 입력은 무음으로 처리한다. 로컬 편집과 공개 배포를 구분하며 자동 업로드하지 않는다.

### F9. 비교 자료와 수집 효과 평가

- **목적:** 보기 좋은 일부 프레임만으로 성공을 과장하지 않고 수집 효과를 판단한다.
- **기대 동작과 경계:** 무작위 후보 100~200장의 contact sheet, 고정 목표 20장의 Top-5, 원본/컬러/흑백/특징 비교, 점수·분포·수집 통계를 만든다.
- **수용 기준:**
  - 샘플링 시드·프레임 목록·후보 목록이 남아 같은 비교를 반복할 수 있다.
  - 1만·10만·조건부 100만 후보의 동일 타깃 평가를 비교하고 좋은 프레임과 실패 프레임을 함께 제시한다.
  - 실제 재생을 보지 못했으면 시각 평가 미실시로 남긴다. MSE 감소만으로 움직임 인식에 성공했다고 판정하지 않는다.
  - 소규모 결과의 시각 품질은 해당 후보 집합에서의 관측으로 기록한다. 충분한 규모·지형·스케일을 탐색하기 전에는 방식 전체의 표현력이나 확대 효과를 부정하는 근거로 삼지 않는다.

### F10. 중단·재개와 단계별 독립 실행

- **목적:** 수집 중단이나 재실행으로 데이터·비용을 낭비하지 않는다.
- **기대 동작과 경계:** 발견·수집·특징·매칭·재추출·렌더·보고를 분리하고 작업 상태, 재시도, 원자적 배치 저장과 자원 한도를 관리한다.
- **수용 기준:**
  - 강제 중단 후 재시작해 완료 배치를 다시 늘리지 않으며, 중간 파일은 완료 데이터로 보이지 않는다.
  - 자원 한도·신호·일시 오류가 발생하면 처리 상태와 다음 재개 위치가 남는다.
  - 중단된 작업과 영구 실패를 구분하고, 한 장면 실패로 다른 완료 데이터를 잃지 않는다.

### F11. 결과 manifest와 출처·권리 기록

- **목적:** “실제 장소” 주장을 검증하고 공개 시 필요한 고지를 준비한다.
- **기대 동작과 경계:** 실제 사용한 촬영 시점·좌표·소스·자산·변환·설정·입력/결과 식별·권리 상태를 기록한다. 좌표 오버레이는 선택이며 프레임별 상세 정보는 별도 목록에서도 제공한다.
- **수용 기준:**
  - 모든 출력 프레임이 하나의 실제 소스 항목과 연결되고 실제 사용 연도로 출처 고지를 만들 수 있다.
  - 촬영일을 수집일로 바꾸거나 지역명을 추정해 사실처럼 표시하지 않는다.
  - 공개용 목록에는 서명 토큰·비밀키·사용자 절대경로가 없으며, 권리 미확인 상태를 확인 완료로 바꾸지 않는다.

### F12. 필요 기반의 소스·검색 개선

- **목적:** 첫 결과의 구체적인 부족을 해결하는 개선만 추가한다.
- **기대 동작과 경계:** NAIP, 추가 스케일, 회전, 경계/SSIM 재정렬, 약한 재사용 페널티를 각각 기준선과 비교한다. 국가·지형·대륙 제한은 AOI/소스 설정으로 표현한다.
- **확정된 개선:** 직각 회전은 기본 검색에 포함하며 각도·크롭·유효 화각을 view ID와 연결해 검색과 출력에 공통 적용한다. 사용자 재생 평가로 32×24 MSE Top-20 검색과 Astra의 연속 최종 선택을 채택했다. 이전 MS-SSIM 최댓값·직접 MSE·형태 우선·독립 상관 검색·더 큰 후보 풀은 비교 결과로 보존한다.
- **수용 기준:**
  - 변경 조건, 별도 결과, 품질/비용 차이를 남기고 채택 여부를 판단한다.
  - NAIP는 실제 읽기·밴드·촬영범위·권리·비용을 확인한 뒤 추가한다.
  - 90/270도 회전은 정사각형이 아닌 화면을 찌그러뜨리지 않고 실제 출력과 검색의 화각을 일치시킨다.

### F13. 검증 후 규모·영상 길이 확대

- **목적:** 닮은 장면을 찾을 기회를 넓히도록 큰 데이터셋을 구축하고 검증된 결과를 전체 작품으로 확장한다.
- **기대 동작과 경계:** 기술적 정확성·자원·접근 조건을 확인하며 가용 범위 안에서 후보를 최대한 확대한다. 100만은 중간 비교 지점이며 확정 상한이 아니다. 30초 이후 전곡, 필요 fps·출력 해상도 확대는 시각 품질을 확인한 후 진행한다. 같은 캐시와 출처 기록 체계를 재사용한다.
- **수용 기준:**
  - 데이터셋 확대 전에 추출·검색의 정확성, 지역·스케일의 범위, 저장·메모리·접근비용 예상과 사용권 상태를 남긴다. 소규모에서의 시각적 성공은 확대의 선행 조건이 아니다.
  - 확대 중 품질과 자원 사용을 기록하고, 중단·상한 결정에는 자원·접근 제약 또는 충분한 탐색 근거를 남긴다. 대규모 수집 자체를 작품 완성으로 대체하지 않는다.
  - 긴 영상에서도 타임스탬프·오디오·프레임 출처가 유지된다.

### F14. 검색 과정을 보여주는 16:9 최종 영상

- **목적:** 원본과 실제 장소 검색의 관계를 이해하며 전곡을 감상할 수 있게 한다.
- **기대 동작과 경계:** 왼쪽 작은 원본, 그 오른쪽 세로 후보 목록, 선택 강조 연결선, 오른쪽 큰 결과 영상을 배치한다. Top-20 전체 평가가 끝난 뒤 최종 선택과 MSE 상위의 다른 네 장소를 MSE 순서대로 표시한다. 선택된 방향을 보존하고 실제 검색 순위와 선택 위치를 구분한다. 선택을 바꿔 보이기 위한 임의 순위 변경은 하지 않는다.
- **수용 기준:**
  - 1920×1080 화면에서 각 원본 프레임의 후보와 선택 사진·강조선이 함께 바뀐다.
  - 타이틀·슬로건·중복 설명 라벨을 넣지 않는다. 경과 시간·프레임 카운터와 후보 점수는 작고 정돈된 위치에 표시한다.
  - 큰 사진 아래에 실제 좌표·촬영일을 한 줄로 표시한다. 확인하지 않은 지명·제목을 생성하지 않는다. 출처 고지는 눈에 거슬리지 않는 작은 글씨로 유지한다.
  - 큰 변환 영역은 한 실제 장소 사진이며 원래 색상·광도를 유지한다. 별도 후보·원본 패널은 설명용이다.
  - 전체 프레임의 Top-K·점수·변환·최종 선택을 기록하고 사진만 나오는 동기화된 영상도 제공한다.

## 비기능 요구사항과 제약

### N1. 실제 사진성과 기본 콘셉트 보존

- **요구와 적용 범위:** 기본 결과의 각 프레임은 한 촬영 자산의 연속된 장소 영역이다. 크롭·리사이즈와 명시한 방향 변경 외에 지형·실루엣을 만들어내지 않는다.
- **이유:** 이 작품의 차별점은 생성이나 모자이크가 아닌 실제 장소 검색이다.
- **수용 기준:** 임의 프레임의 원본 재추출·변환 기록으로 확인한다. 흑백/명암 반전 등 실험은 별도 라벨과 결과로 분리한다.

### N2. 재현성과 데이터 정합성

- **요구와 적용 범위:** 동일 입력·고정 후보 집합·설정·시드·코드/의존성에서 매칭 목록을 재생성한다. 원격 데이터가 바뀌어도 최종 사용 이미지와 manifest를 보존한다.
- **이유:** 품질 비교와 출처 확인에 필요하다.
- **수용 기준:** 재실행의 타깃·타일 ID·선택 순서가 같고 인덱스 정합성이 검증된다. MP4 바이트 일치와 논리적 매칭 일치는 구분한다.

### N3. 제한된 자원과 측정 가능한 확장

- **요구와 적용 범위:** CPU에서 시작하고 원본 장면 전체나 후보 컬러 전체를 RAM에 올리지 않는다. 배치·메모리·디스크·수집량·네트워크 동시성 상한을 둔다.
- **이유:** 실제 작업 환경이 아직 확인되지 않았으며 무제한 수집은 가치가 없다.
- **수용 기준:** 실측 자원 사용과 설정 상한을 보고한다. 전체 거리 행렬 대신 배치 Top-K를 사용하고 공간 부족 시 안전하게 멈춘다.

### N4. 권리·비용·비밀정보 경계

- **요구와 적용 범위:** 원본 MP4는 로컬에 유지하며 공개 영상 데이터도 제공 서비스 정책을 따른다. 비밀키·서명 URL을 기록하지 않고 승인 없는 과금을 하지 않는다.
- **이유:** 공개 라이선스와 무료 접근, 영상 소유와 공개 이용 권한은 서로 다르다.
- **수용 기준:** 소스별 조건·사용권 상태가 manifest에 남고 공개 기록과 Git에는 민감 정보가 없다. Requester Pays가 기본 비활성이다.

### N5. 로컬 실행성과 경로 독립성

- **요구와 적용 범위:** uv로 관리하는 Python 3.11+·FFmpeg 중심의 로컬 CLI/배치 도구로 구현한다. 특정 개인 경로·GPU·서버·LLM 계정에 의존하지 않는다.
- **이유:** 다른 AI/개발자에게 ZIP만 전달해 작업을 이어갈 수 있어야 한다.
- **수용 기준:** 실제 검증한 플랫폼·설치법만 README에 표시하며 공백·한글이 포함된 로컬 입력 경로를 처리한다.

### N6. 정직한 성과·미검증 표기

- **요구와 적용 범위:** 실제 영상 접근, 데이터 수집, 수치 평가, 시각 평가, 권리 확인을 각각 구분한다.
- **이유:** 엔지니어링 성공과 작품 성공은 다르고 이 프로젝트는 실험적이다.
- **수용 기준:** 실패·미확인·차단이 보고서에 남고 더미 성공 파일이 없다. 시각적 실패를 원본 합성으로 감추지 않는다.

### N7. 단순한 구현과 역할에 맞는 문서

- **요구와 적용 범위:** 요구사항·기술·진행 상태·사용법을 분리하고 F/N/P 연결을 유지한다. 빠른 결정적 테스트와 작은 작업 단위를 선호한다.
- **이유:** 장기적인 반복 실험에서 과도한 추상화와 중복 문서가 판단을 흐린다.
- **수용 기준:** 주요 요구가 설계·단계·검증 근거로 연결되며 버그 수정 이력을 SPEC/README 본문에 누적하지 않는다. 네트워크 검증을 단위 테스트의 기본 실행에 섞지 않는다.
