# P6 — 다중 해상도 ZNCC·Gradient Correlation 독립 검색

## 요청과 판단

사용자는 같은 Top-20 비교에서 MS-SSIM을 선호한 뒤, 다중 해상도 ZNCC와 Gradient Correlation을 전체 검색에 사용하는 첨부 검토를 참고해 진행하도록 요청했다. 첨부는 `d25fb64` 시점의 다섯 장소 재평가를 분석한 자료다. Top-20 전체 재평가는 이미 `280bd59`에서 구현했지만 MSE 밖의 후보를 찾지 못하는 한계는 남아 있어, 이번에는 독립 검색과 후보 확대를 구현한다. 첨부의 우월성·최적값 제안은 검증된 결과로 취급하지 않는다.

관련 요구는 F6·F9·F12·N1–N3·N6다. 이전 PHOG/SDF/Chamfer 전수 검색을 되살리지 않으며 실제 사진의 연속 명암과 부호 있는 미분을 비교한다. 새 지표 전수 검색의 효과와 최종 선택 지표의 효과를 구분한다. 전곡의 기본 설정은 이번 비교만으로 교체하지 않는다.

## 설계와 실행 범위

전체 100만 장소·400만 회전 view에서 16×12·32×24 정규화 명암 ZNCC와 두 크기의 signed Gradient Correlation으로 각각 Top-512를 찾는다. 두 경로와 기존 MSE Top-20의 합집합을 64·128픽셀 폭에서 평가한다. MSE 후보를 보존하므로 같은 후보군에서 기존 MS-SSIM을 재현하고 넓은 MS-SSIM의 선택도 볼 수 있다. 중복 view만 합집합 단계에서 제거하며 장소 중복은 평가 뒤에 정리한다.

기존 MSE packed view 주소·coarse 특징·정렬 키를 재사용하고 `uint8` fine 배열만 같은 행 순서로 약 3.072GB packing한다. 후보 배치를 바깥 루프로 하여 정규화 명암/미분을 한 번 계산하고 모든 타깃 배치에 사용한다. 약 46GB의 추가 float32 특징을 저장하는 대신 필요한 배치만 메모리에 둔다. 실수 내림차순 Top-K를 새로 구현하며 기존 MSE의 정수 내적 변환을 사용하지 않는다. 원본 검색 계산 공유는 16·32 원배열이 모두 같은 경우만 허용한다.

정밀 구조 점수는 ZNCC `.7`·GC `.3`이다. 원본의 흰/검정 영역에 해당하는 사진의 평균 명암 차이 `.08` 이상, 사진 명암 표준편차 `.02` 이상, 양의 ZNCC를 요구한다. 최고 구조 점수에서 `.01` 이내의 후보는 원래 명암 MSE로 선택한다. 이 수치는 설정 파일로 바꿀 수 있는 최초 가설이며 튜닝으로 최적화한 값이 아니다. ZNCC 단독과 GC 단독에도 같은 대비·밝기 규칙을 적용한다. 허용 후보가 없으면 MS-SSIM Top-20, 표준편차 `.005` 미만 단색 타깃은 원래 MSE로 처리하며 사유를 기록한다. 두 MS-SSIM 비교에는 새 대비 guard를 적용하지 않는다.

GC는 [가로·세로 NCC의 평균 정의](https://pmc.ncbi.nlm.nih.gov/articles/PMC4640192/)를 따른다. Gaussian σ1·radius3·reflect 미분, 축별 평균 제거와 단위 L2 정규화, 두 해상도의 동등 가중 평균이다. 분산 없는 축은 0으로 기여한다. [OpenCV ZNCC 정의](https://docs.opencv.org/4.x/df/dfb/group__imgproc__object.html)의 명암 극성을 보존하며 출력 사진은 바꾸지 않는다. 해당 문헌은 다른 등록 문제의 근거이며 Bad Apple 검색에서의 개선을 보장하지 않는다.

비교 구간은 이전과 같은 38–48초의 모든 원본 300프레임이다. 각 단계는 로컬 RGB·특징·출처만 사용하며 원격 읽기·유료 데이터·외부 업로드가 없다.

## 구현·검증

`production/correlation/`에 특징·검색·정밀 평가·비교 실행을 응집시켰다. `compare-correlation` CLI와 `config/correlation.json`이 실행 경계다. 기존 2×3 비교 화면의 그리기 함수를 재사용하며 지표명·검색 경로 순위·점수·시간·프레임 카운터만 표시한다. 모든 패널은 같은 canonical RGB·표시 크기이고 비교 영상은 무음이다.

최종 오프라인 테스트 7개가 8.79초에 통과했다. 새 검증은 밝기/대비 변화·극성 반전·단색의 유한한 특징, 실수 소수부와 전역 동률을 보존하는 배치 Top-K, 실제 대비 조건과 구조 허용폭 내 밝기 선택·fallback, 제외·재배열 후에도 보존되는 출처 행 주소와 bulk RGB 읽기의 원본 픽셀 보존이다. 나머지는 기존 MS-SSIM·화면 선택 계약이다. 초기 확인에서 기존 세 비교 지표 테스트도 통과했다. 전체 테스트나 수신 확인용 재다운로드는 하지 않았다.

## 실행 중 최적화

넓은 검색에서는 검색 후의 출처 해석과 RGB 읽기 비용이 커졌다. 공통 `production/search.resolve()`는 source shard 전체를 Python 객체로 바꾸던 처리를 선택된 Arrow 행만 `take()` 후 변환하도록 바꿨다. 새 경로는 view 주소 구간별 여덟 작업으로 메타데이터를 해석하고 완료 부분을 Parquet으로 보관한다. 출처 주소 테스트와 실제 기존 기준선 재현으로 정확성을 확인한다.

정밀 평가의 RGB는 `matching/photos.read_rgb_rows()`로 필요한 사진 행만 정렬·중복 제거해 연속 바이트로 읽는다. 작은 mmap 랜덤 읽기의 page fault를 줄이고, shard 전체를 읽어 사용하지 않는 사진까지 전송하는 비용도 피한다. 실제 단일 표본 프로파일에서 112장·16,429,184바이트 shard 전체 읽기는 약 .182초, 다른 표본의 mmap 사진 한 장 읽기·명암 변환은 약 .237초, 선택 행 146,688바이트 bulk 읽기는 약 .00054초였다. 파일·캐시 상태를 통제하지 않은 표본이므로 이 수치로 전체 개선 배수를 주장하지 않는다. 같은 점수 프로파일의 MS-SSIM 쌍 계산은 약 .861ms, 다른 점수는 약 .077ms여서 계산보다 저장소 접근을 우선 개선했다. 완료한 검색과 점수 배치를 유지하고 중단·재개했으며 영상 프레임이나 후보 수를 줄이지 않았다.

## 산출물과 평가 범위

`comparison.mp4`는 10,448,317바이트, 1920×1080 H.264, 300프레임·30000/1001fps·10.010초·무음이다. 위쪽 원본·기존 MS-SSIM Top-20·확대 MS-SSIM, 아래쪽 확대 ZNCC·GC·ZNCC+GC 순서다. 사진 아래의 `Z#`·`G#`는 두 검색 경로의 실제 순위이고 `—`는 그 경로 Top-512 밖이라는 뜻이다. 시간·프레임 카운터와 작은 출처 고지를 유지한다.

고유 출처 `candidates.parquet` 43,056행, 프레임별 후보 `shortlists.parquet`와 점수 `evaluations.parquet` 각 249,771행, 다섯 방법 선택 `selected.parquet`와 최종 표시 후보 `display-five.parquet` 각 1,500행을 남겼다. 실제 source PTS·좌표·촬영일·원본 창·회전은 `dense_row`로 연결한다. `retrieval.npz`, `metadata/`, `scores/`는 재개 캐시다. 기본 전곡 파일은 변경하지 않았다.

영상 메타데이터는 ffprobe로 한 번 확인하고 대표 화면을 열어 배치·숫자·실제 사진을 확인했다. 이 실행은 동일 10초 구간의 비교다. 새 경로의 전곡 실행, 전체 주관적 재생 평가와 기본 선택 채택은 미실시다. 확대 MS-SSIM도 두 상관 검색 경로와 MSE의 합집합 안에서 고른 결과이며 400만 view 전부에 MS-SSIM을 전수 적용한 결과는 아니다.
