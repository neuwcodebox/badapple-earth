# P5 — 병행 수집의 부분 종료 복구

관련 요구: F5, F10, F13, N2–N4, N6. 사용자의 진행 확인 요청 시 일부 소스의 조기 종료를 발견해 기존 추가 수집·인덱싱 작업을 복구한다.

## 관측과 원인 범위

11월 7일 **12:08 KST**에 신규 **186,774개**, 인덱싱 **180,261개·4,326,264 view**를 확인했다. 네덜란드·스위스와 인덱싱은 동작 중이었으나 NAIP part-02가 `PermissionError`로 34,362개에서 끝났고, LINZ part-01은 할당 재배분 종료 뒤 49,889개로 목표 50,000개에 111개 미달했다. NAIP part-01과 LINZ part-02는 각 50,000개 완료 상태다.

NAIP의 manifest는 34,362개, SQLite ledger는 34,244개였다. 공개된 shard와 ledger 사이의 차이는 기존 `Index.recover()`로 재적용할 수 있다. 원래 CLI가 파일 경로를 숨겨 정확히 어느 파일 접근에서 오류가 났는지는 미확인이다. 병행 읽기가 있는 Windows의 일시적 파일 접근 거부 가능성을 고려해 `write_json`의 원자적 교체에만 최대 8회·최대 회당 0.5초의 유한 재시도를 추가했다. 계속 거부되면 실패를 그대로 알리고 기존 공개 파일·완성된 임시 파일을 보존한다.

## 실행과 인계

`.local/recover_expansion_20261107.py`를 **12:11 KST**에 실행했다. NAIP part-02와 LINZ part-01만 같은 설정·목표·경로에서 재개하며, 완료한 다른 part와 기존 120만은 다시 수집하지 않는다. 기존 네덜란드·스위스의 네 writer와 별도로 복구 writer 두 개가 한시적으로 동작한다. 기존 메모리·디스크·요청 재시도 상한은 유지한다.

원래 제어기는 소스별 실패 결과를 메모리에 보관하므로, 복구 제어기는 원래 제어기의 종료를 기다린 뒤 최신 소스 보고서를 읽어 최종 상태와 참조 결합을 정리한다. 모두 실제 목표를 달성한 경우에만 완성된 150만 결합으로 기록한다. 인덱서가 앞선 부분 종료를 보고 멈췄으면 저장한 그룹에서 자동으로 다시 실행한다. 전체 타일 중복 검사는 하지 않는다.

- 복구 상태: `.local/expansion-recovery-20261107.json`.
- 복구 로그: `.local/recovery-{naip,linz}-20261107.log`.
- 현재 복구 실행 세션: **99539**. 수집 **9364**, 인덱싱 **21464**와 함께 관리한다. 세션 번호는 재부팅 뒤 재사용하지 않는다.
- 사용자 일시중지 표식을 확인하면 복구 자식 writer도 종료하고 체크포인트를 보존한다. 사용자 중단 요청 시 이 복구 실행도 함께 멈춘 것을 확인해야 한다.

원자적 공개의 일시·영구 접근 거부와 기존 수집·병렬·복구 테스트 **9개가 통과**했다. 테스트는 고정 대기 시간에 의존하지 않는다. **12:13 KST**에 NAIP가 34,621개, LINZ 해당 part가 49,899개로 증가해 실제 복구 저장을 확인했다. 당시 신규 총량은 194,350개, 인덱싱은 187,627개·4,503,048 view였다. 복구·전체 30만 수집이 완료됐다는 뜻은 아니다.
