# P6 — 추가 30만 후보를 적용한 흑백 전곡

## 범위와 실행 상태

사용자가 수집·인덱싱 완료 후 새 후보의 매칭·영상 제작을 요청했다. 11월 7일 15:25 KST에 실제 검색을 시작했다. **영상 완성·재생 개선은 아직 미확인**이다. 기존 전곡과 입력 MP4는 보존한다. 관련 요구사항은 F1, F5–F11, F13, F14, N1–N7이며 설계 계약은 TECH의 silhouette 검색·명암 선택에 둔다.

- 결합 인덱스: `data/index/p5-aerial-1.5m`, 저장된 후보 항목 1,500,000개. 타일 중복 검사는 하지 않았다.
- 신규 준비 묶음: `data/prepared/p5-expand-300k`, 43개, 부모 300,000장·view 7,200,000개.
- 재사용 기준: `data/runs/p6-silhouette-color-full`, 기존 1,200,000장·28,800,000 view 검색과 정밀 점수.
- 타깃: 같은 MP4의 218.5초 이전 source PTS 6,549개, 고유 32×24 질의 6,415개.
- 형태 출력: `data/runs/p6-silhouette-shape-1.5m-full`.
- 흑백 최종 출력: `data/runs/p6-silhouette-luminance-1.5m-full`.

## 재사용과 중단 계약

입력 참조 run은 기존 타깃·기준 MSE 후보를 hard link 또는 복사로 공유하고 결합 인덱스만 새로 연결한다. 기준 view 주소를 보존한 뒤 신규 묶음의 직각 4방향과 추가 20개 affine view를 붙여 총 36,000,000 view 주소를 구성한다. 검색은 기준 Top-K를 seed로 사용해 추가 7,200,000 view만 읽는다. 같은 타깃·metric·K·기준 source 범위를 검증하며 기준 입력을 바꿔 기존 결과로 가장하지 않는다.

새 검색 후보와 이전 형태·표시 후보를 합친다. 프레임/view 쌍 단위로 기존 점수를 제외하므로 이전에 평가된 프레임도 새 사진은 평가한다. 현재 후보 쌍만 기존 점수에서 추려 형태 허용폭 .02·최대 24개를 유지한다. 색상 선택·중간 컬러 렌더를 생략하고 같은 명암 연속성 가중치 .2와 흑백·큰 사진·한 줄 메타데이터 배치를 적용한다. 기존 native 사진을 재사용하며 처음 필요한 선택 사진의 상세만 읽는다.

```powershell
$env:OPENBLAS_NUM_THREADS='8'
$env:OMP_NUM_THREADS='8'
$env:NUMBA_NUM_THREADS='8'
uv run python -m badapple_earth.production.silhouette.expansion --resume
```

`--pause`는 형태·명암 출력 모두에 중단 표식을 남긴다. 검색은 체크포인트에서, 평가는 실행 중 배치를 저장한 뒤, 렌더는 완료 구간을 보존하며 멈춘다. 재개 명령이 두 표식을 해제한다. 갑작스러운 종료에도 확정된 배치·선택·인코딩 구간을 재사용한다. 수집·이전 전곡·취소된 규모 비교는 다시 실행하지 않는다.

## 검증

추가 검색은 작은 결정적 시험에서 전수 검색과 점수·순위가 정확히 같았으며, 중단·재개 후에도 새 source 배열만 읽었다. 기준 source identity 변경은 거부했다. 같은 슬롯의 새 view 및 같은 view의 새 슬롯은 점수 재사용에서 제외하지 않는 계약도 검증했다. 관련 silhouette 테스트 **29개 통과**. 첫 테스트 실행은 샌드박스 임시 디렉터리 생성 오류가 있어 저장소의 별도 `--basetemp`로 실행했다.

실제 신규 prepared metadata를 결합 인덱스로 해석하는 오프라인 확인에서 NAIP·LINZ·Swiss의 출처 주소와 RGB cache 경로를 확인했다. 정상 완료된 이미지를 다시 다운로드하거나 전체 타일 중복 검사를 수행하지 않았다. 실제 검색의 첫 체크포인트에서 기준 28,800,000 view를 재사용하고 추가 view만 진행하는 것을 확인했다. 정밀 평가·선택·영상·시각 품질은 실행 완료 후 기록한다.
