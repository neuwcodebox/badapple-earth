# P6 — 실제 사진의 위치·확대·회전을 맞추는 전곡 제작

## 요청과 현재 상태

사용자가 같은 사과 모양이라도 위치가 바뀌면 기존 사진을 못 쓰는 문제를 지적하고, 빠른 정합 알고리즘과 필요한 후속 작업 전체를 요청했다. 설명·짧은 실험에서 멈추지 않고 전곡 제작까지 수행한다. 기존 150만 명암 전곡과 모든 원본·캐시는 보존한다. 관련 요구는 F6/F7/F8/F10/F11/F14와 N1/N3/N6, 설계는 TECH의 연속 프레이밍이다.

전곡 정합은 17:42 KST, 후속 추적·영상 변화 선택과 최종 두 영상은 **18:04:36 KST에 완료·검증**했다. 최종 출력은 `data/runs/p6-tracked-1.5m-full/`, 설정은 `config/tracking-full.json`이다. 기준 명암 영상과 중간 정합 결과 `data/runs/p6-registered-1.5m-full/`를 보존한다. 대표 정지 화면과 연속 프레임 시트는 확인했고 전체 재생 평가는 남아 있다.

## 계산 구조와 근거

- 검색: 기존 32×24 배열의 저주파 Fourier magnitude 44차원 정규화 내적. 순환 이동에 대한 위상 불변성을 이용하되, 실제 비순환 잘림·극성·형태의 정답을 보장하는 점수로 쓰지 않는다. 모든 이동 위치를 별도 인덱스로 늘리지 않는다.
- 후보: 추가 Top-24, 현재 상위 형태 후보와 앞뒤 0.5초 7개 시점의 기존 선택을 합쳐 **198,002개** 실제 프레임/view 조합을 만들었다. 같은 파일·사진·각도의 반복 정합은 묶어서 처리한다.
- 거친 정합: 80px 원본에서 여러 각도·확대율의 모든 유효 정수 이동 위치를 OpenCV template matching으로 비교한다. 현재 설정은 각도 보정 −12/0/+12°, crop .5/.7/.85/1이다. 유효 영역의 적분합으로 원본 밖 회전 모서리를 제외한다.
- 정밀 정합: 프레임별 상위 6개를 이동 2변수·확대율·회전각의 bounded least squares로 보정한다. 실제 RGB에서 기존 64/128 영역·경계와 signed gradient 점수·시인성을 재측정한다. 거친 위치와 연속 보정 위치 모두 후보로 유지한다.
- 추적: phase correlation으로 초기화한 ECC affine을 similarity로 투영하고 신뢰도·회전·확대 범위를 확인한다. 같은 원본 구간의 앞뒤 최대 15프레임에서 좋은 실제 사진의 프레이밍을 원본 움직임에 따라 전파하고, 그 주변에서 prior를 둔 국소 정합을 수행한다.
- 시간축: 시인성을 통과한 기존 선택은 남기며 새 후보는 그 형태 점수 이상이어야 한다. 비시인성 fallback은 유효한 새 후보가 있을 때 교체하고, 단색 타깃은 보존한다. 영역별 명암 거리, 같은 사진의 기준점 이동과 모든 후보 사진 사이의 motion-compensated 명암 영상 차이로 전곡 경로를 고른다. 유지 보너스·최소 유지 시간은 없다.
- 출력: 한 실제 사진 안에서만 팬·줌·회전한다. bilinear 보간 방식·행렬·원래 window·실제 원본 사각형·footprint·중심 좌표를 기록한다. 기준 사진·점수·타깃 특징은 재계산하지 않는다.

## 검증과 실행

관련 오프라인 테스트 52개가 통과했다(정합·추적 계약 19개, 기존 affine 33개). 이동·확대·회전한 형태 복원, 전 범위의 원본 내부 네 모서리, 변환 후 지리 좌표와 자산 추적, 움직이는 원본을 따라가는 시간축 선택, 시인성·기준 형태 점수 보존, 검색 체크포인트 재개를 확인했다. 사진 ID가 다른 후보의 영상 변화 비교, 원본 회전·확대 추정과 좋은 사진의 이웃 프레임 전파도 검증했다. 현재 사진과 이웃에서 좋았던 사진은 거친 순위가 낮아도 정밀 후보에서 빠지지 않게 보장했다. 합성 영상은 단위 테스트에서만 쓰며 실제 품질 성과로 보고하지 않는다.

실제 4828번 프레임 자료를 이용한 단일 프로세스 확인에서 캐시가 준비된 거친 정합 약 .005–.006초, 연속 보정 약 .003–.009초를 관측했다. 최초 읽기·라이브러리 초기화와 전수 검색이 CPU를 사용하는 동안에는 느렸으므로 이 수치를 전곡 총 시간으로 외삽하지 않는다. 추가 전수 검색은 기존 3,600만 view를 **692.272초**에 처리했다. 정합·사진 준비·렌더는 17:05–17:42, 완료된 검색·정합·픽셀을 재사용한 후속 추적 전체는 **17:57:18–18:04:36, 약 7분 18초**였다. 구현 중 재개·수정 시간도 포함한 실행 벽시계이며 순수 알고리즘 벤치마크가 아니다.

실제 원본 RGB·타깃 특징·출처로 정밀 경로를 확인한 4828번 프레임은 같은 사진의 기존 형태 점수 .690085에서 이동·확대·회전 보정 후 .703982, 시인성 통과였다. 중심 좌표와 원래 자산도 연결했다. 한 프레임의 확인이며 전곡 성과로 취급하지 않는다. 원본 출처 해석 362개 배치를 보존한 상태에서 후보 유지 보장을 반영해 재개했고, 프레임마다 반복되던 파일 경로 resolve 호출도 사진/목표 디렉터리별로 묶었다.

작은 타깃 PNG를 후보마다 여는 비용을 줄이기 위해 6,549개의 정확한 256×191 uint8 픽셀을 약 320MB의 read-only 공유 mmap으로 묶었다. 기존 PNG와 같은 값이며 작업자별 파일 재읽기를 하지 않는다. 준비는 256프레임씩 재개하며 파일 게시와 완료 상태 기록 사이에 종료돼도 확정된 배열을 덮어쓰지 않는 회귀 테스트를 통과했다. 진행 중 거친 정합 배치를 유지하고 캐시를 적용해 재개했다.

새 프레이밍의 네 모서리가 이전 native 사진의 실제 영역 안에 들어오면, 이전 변환의 역행렬과 새 변환을 합성해 고해상도 픽셀을 재사용한다. 범위를 벗어나면 재사용하지 않고 필요한 원본 상세를 읽는다. 재사용한 view·이전 view·상대 행렬·bilinear 방식은 `native-reuse.json`에 기록한다. 기존 crop 안에서의 정확한 재표본화와 밖으로 나간 경우의 거부를 테스트했다. 거친 정합 1,471개 배치는 17:30 KST에 모두 저장했다.

정밀 보정 502개 배치를 약 147초에 완료했다. 후속 검사에서 이전 비시인성 fallback 중 47프레임에 유효한 새 정합이 있었으나 최초 시간축 선택은 이 중 10프레임에서 밝기 연속성 때문에 fallback을 남기는 것을 확인했다. 유효한 새 후보를 우선하도록 선택 조건과 회귀 테스트를 보완했다. 초기 선택만 별도 보관하고 검색·출처·거친/정밀 정합·사진 캐시는 모두 재사용해 최종 선택부터 이어갔다.

최초 정합의 평균 형태 점수는 .56877이었지만 사진 교체는 기준 2,777회 그대로였고, 비교 가능한 같은 사진의 phase 이동 잔차는 .000708→.003442로 늘었다. 프레임별 독립 보정만으로 종료하지 않고 원본 similarity 이동·좋은 프레이밍 전파·움직임 prior와 사진 ID를 가리지 않는 영상 차이 선택을 추가했다. 원본 이동 준비는 약 6초, 기존 후보 영상 특징 170배치는 약 4.99초였으며 전수 검색과 거친 정합은 다시 수행하지 않았다.

## 표시 후보의 품질 조건

사용자가 후보가 다섯 개씩 보이지 않는 이유를 물었고, 개수를 억지로 채우기보다 알고리즘에 맞게 표시하도록 요청했다. 기존 구현은 시간축 선택용으로 기준 선택 이상의 점수만 남긴 목록을 화면에서도 사용했다. 표시용 후보를 실제 정합·평가 결과에서 별도로 만들도록 수정했다. 시인성 통과, 프레임 최고 형태 점수에서 .025 이내, 장소별 최고 프레이밍, 최종 선택 포함 조건으로 최대 다섯 곳을 표시한다. 단색·비시인성 fallback은 한 장이다. 후보를 채우기 위한 추가 검색·사진 복제·저품질 대안은 사용하지 않는다.

실제 표시 수는 1개 4,728프레임, 2개 1,419프레임, 3개 315프레임, 4개 70프레임, 5개 17프레임이다. 이전 1개 3,658·2개 2,215·3개 557·4개 98·5개 21보다 줄어든 장면도 있으며 개수 증가를 목표로 삼지 않는다. 6,549프레임에서 장소 중복 없음·1–5개·선택한 정확한 프레이밍 포함·점수 순위·품질 조건을 검사했다. 4,809번의 실제 다섯 후보 화면 `preview-display-check.png`를 확인했다. 관련 단위/인코딩 계약 테스트 24개가 통과했다.

원래 선택의 view ID·변환·source PTS는 그대로 보존하고 검색·정합·추적을 재실행하지 않았다. 비교 영상만 별도 segment에 렌더하고 사진 전용 영상은 재인코딩하지 않았다. **18:23:49 KST에 갱신과 두 출력의 프레임·해상도·AAC 검증을 완료**했다. 수정 전 테이블·비교 영상은 `display-before-quality-shortlist/`, 갱신 상태와 표시 수는 `display-refresh.json`에 둔다.

## 실행과 재개

```powershell
$env:OPENBLAS_NUM_THREADS='8'
$env:OMP_NUM_THREADS='8'
$env:NUMBA_NUM_THREADS='8'
uv run python -m badapple_earth.production.registration.pipeline --resume
uv run python -m badapple_earth.production.registration.tracking --resume
```

중단은 같은 명령의 `--resume` 대신 `--pause`다. 검색 체크포인트·출처 배치·거친/정밀 정합 배치·선택·사진·인코딩 구간을 저장하고 재개한다. 네트워크 읽기는 처음 필요한 선택 사진의 상세를 준비할 때만 수행한다. 원본 MP4는 수정·재다운로드·외부 업로드하지 않는다.
