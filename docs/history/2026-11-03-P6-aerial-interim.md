# P5/P6 — 수집과 병행하는 항공사진 중간 전곡

관련 요구: F2, F5–F11, F13, F14, N1–N4, N6. 사용자가 수집한 중간 결과를 먼저 영상에 반영하고 수집·인덱싱·제작을 병행하도록 요청했다. 수집 완료를 기다리는 제작 조건을 제거하고 기존 계산을 재사용한다. 기존 입력 MP4·Astra 전곡·수집 작업은 유지한다.

## 고정 후보와 병행 실행

네 수집 인덱스에서 이미 공개된 **131,800개** 후보를 `data/index/p5-aerial-interim-new`에 고정했다. 기존 100만과 합친 `data/index/p5-aerial-interim`은 **1,131,800개 장소·4,527,200개 회전 view**다. 수집이 뒤에서 늘어나도 이 영상의 후보 수는 변하지 않는다. 물리 원본 인덱스와 shard를 보존해야 하며 RGB·특징을 복제하거나 확인용 재다운로드를 하지 않는다.

수집기는 원래부터 RGB와 16×12·32×24 명암·직각 회전 특징을 같은 배치에 공개한다. 별도의 전체 특징 재계산은 필요하지 않다. 중간 제작에서 필요한 추가 packing은 저장된 131,800개 후보의 **527,200개 view만** 읽어 만들었다. 스냅샷별 회전 캐시 manifest는 수집기의 계속 늘어나는 행 목록과 분리된다.

기존 100만의 메타데이터까지 다시 순회하던 결합 시도는 읽기 단계에서 중단하고, 이미 중복 검사한 bundle의 서로 다른 source namespace를 검증해 참조·통계를 재사용하는 `--disjoint-sources`로 완료했다. 공개 shard·RGB는 변경하지 않았다. 사진은 전부 복사하지 않고 실제 표시·선택에 필요한 항목만 재사용하도록 중간 제작 경로를 정리했다.

## 정확한 추가 검색과 평가 재사용

기준선은 `data/runs/p6-grid32-full`의 모든 **6,955개 source frame·32×24 MSE Top-20·네 직각 회전**이다. 기존 100만의 Top-20과 추가 후보의 Top-20을 SSE·view ID로 합쳐 전체 후보의 정확한 Top-20을 얻는다. 입력·쿼리 매핑·격자·점수·K·회전과 후보 합집합을 검증했다. 기존 dense row를 유지하고 추가 view는 4,000,000 offset을 사용하므로 원래 평가 캐시도 정확히 연결된다.

실제 실행은 기존 **1,000,000개 장소를 재검색하지 않고 131,800개만 검색**했다. MS-SSIM 평가 139,100건 중 **136,019건 재사용·3,081건 신규 계산**, 신규 점수 배치의 관측 경과는 약 **23.2초**다. 기존 타깃 프레임·후보 사진·선택 원본 디테일도 로컬 캐시를 재사용한다. BLAS/Numba 각 4스레드, 점수 작업 4개, 원본 디테일 읽기 2개, 렌더 작업 2개·encoder 2스레드로 수집과 병행한다. GPU·유료 데이터·클라우드는 사용하지 않았다.

추가 후보의 실제 32×24 검색 계산은 약 **54.3초**, packing·메타데이터 해석·Top-K 결합을 포함한 검색 단계는 약 **282.7초**였다. 기존 후보의 서로 다른 view 메타데이터 17,753개도 재사용했다. 시간은 이번 로컬 실행 관측치이며 다른 수량·환경의 보장 시간이 아니다.

이 중간 영상의 선택 방식은 MS-SSIM이다. 기존 Astra 전곡을 새 후보에 적용했다고 표시하지 않으며 전곡 기본 설정을 덮어쓰지 않는다. 실제 원색 사진·방향·크롭과 원본 모든 PTS·오디오를 유지한다. 항공사진의 고해상도 선택 사진도 소스별 접근 경로로 읽고 실제 licensor·촬영 단일 날짜/구간을 프레임·credits에 반영한다.

## 실제 관측과 검증

- `selected.parquet`: Sentinel-2 **6,829프레임**, LINZ **90프레임**, NAIP **36프레임**. 총 6,955프레임이며 선택 view는 1,496개다. 신규 항공사진이 실제 선택된 126프레임을 확인했다. 전체 영상의 지각 품질 향상으로 일반화하지 않는다.
- 평균 검색 Best MSE는 같은 32×24 기준선 **0.0673249152 → 0.0673035061**이다. 최종 MS-SSIM 선택 점수·재생 평가는 별개다.
- 진행 중 원본 source manifest가 늘어나도 고정 후보를 읽는 계약, descriptor 변경 거부, 재실행 시 고정 후보 유지, 서로 다른 namespace의 빠른 결합, 전체 순위와 추가 Top-K 합병의 일치·동률·dense offset, 기존 사진 무네트워크 재사용·촬영 구간 표시·점수 캐시의 검증된 재사용을 테스트했다.
- 스냅샷·수집·검색·제작 관련 테스트 27개, 추가 점수 캐시 계약을 포함한 증분 테스트 7개가 통과했다. 동일한 스냅샷의 재실행 유지도 확인했다. 실제 검색·점수·원본 디테일 준비와 전곡 렌더링을 완료했다.

2026-11-03 **21:55:40 KST**에 중간 전곡을 완료했다. 제작 제어기 시작 21:42:58부터 약 **12분 42초**이며 앞선 코드 구현·스냅샷 준비 시간은 제외한다. 선택 사진 원본 디테일은 기존 캐시를 재사용하고 필요한 신규 27개 view를 추가 읽었으며 신규 결과는 모두 `native`로 완료했다.

FFprobe로 설명 영상 1920×1080·사진 전용 1444×1080, 두 영상 모두 H.264·6,955프레임·30000/1001fps·232.065167초, 원본 AAC 9,997프레임·232.129887초를 확인했다. 타깃·frame plan·실제 선택의 모든 source PTS/time base가 일치한다. 파일 크기는 각각 177,149,175bytes와 191,081,013bytes다. 실제 LINZ 선택인 slot 357의 `aerial-frame.png`에서 원색 사진·후보·실제 순위·선택 연결선·촬영 구간·CC BY/licensor 표시를 확인했다. 대표 화면의 검증이며 전체 재생 품질 평가는 아직이다.

## 실행과 산출물

```powershell
$env:OPENBLAS_NUM_THREADS='4'
$env:OMP_NUM_THREADS='4'
$env:NUMBA_NUM_THREADS='4'
uv run badapple-earth produce --config config/production-aerial-interim.json --output data/runs/p6-aerial-interim
```

같은 명령으로 중간 스냅샷의 packing·추가 검색·평가·완료 영상 segment를 재사용하며 재개한다. 실제 상태는 `data/runs/p6-aerial-interim/manifest.json`, 고정 후보는 `.local/aerial-interim-snapshot.json`에서 확인한다. 산출물은 `final-16x9.mp4`, `satellite-full.mp4`, `preview.png`, `selected.parquet`, `frame-plan.parquet`, `search/matches.parquet`, `credits.json`이다.

별도 프리셋은 현재 작업 공간의 MS-SSIM 설정에서 만들었다. 먼저 존재하던 후보 표시·수동 검토 관련 미커밋 변경은 보존했으며 이번 스냅샷/증분 제작 커밋에 포함하지 않았다.

수집 완료 후의 별도 120만 결합·기존 10초 규모 비교 경로도 유지한다. 그 경로의 결합은 기존 100만을 다시 읽지 않도록 갱신했다. 중간 1,131,800개를 최종 120만 완료로 표시하지 않는다.
