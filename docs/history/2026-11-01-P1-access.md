# P1 — uv 실행 환경과 소량 실제 데이터

- **날짜:** 2026-11-01 (Asia/Seoul).
- **관련 요구:** F1, F2, F7, F11, N1–N7.
- **범위:** Python 환경, 로컬 MP4 검사, 실제 Sentinel-2 샘플 읽기와 출처 기록. 대량 수집기·검색·렌더링은 미구현이다.

## 판단과 현재 방향

Python 설치·환경·의존성·실행은 uv로 통일한다. 데이터셋은 가용 자원·접근 조건 안에서 최대한 넓고 다양하게 구축하며 1만·10만·100만은 중간 비교 지점이다. 작은 표본은 기술적 동작을 확인하는 자료이며 시각적 성공을 확대의 선행 조건으로 요구하지 않는다. 최대 규모를 무제한 실행이나 유료 데이터·대규모 클라우드 실행 승인으로 해석하지 않는다.

검증은 필요한 최소 범위로 수행한다. 이번 P1에서 재추출과 별도 HTTP range 확인까지 수행했으나, 이후 정상 완료된 다운로드를 확인하려고 재수신하거나 같은 검사를 반복하지 않는다. 실행 오류·명백한 결과 이상·변경 위험이 있을 때 필요한 확인을 한다.

## 구현과 환경

- `pyproject.toml`, `uv.lock`, `.python-version`과 `src/badapple_earth/`, `tests/`, `config/`를 추가했다.
- CLI는 `probe`, `sample`, `verify-sample` 세 명령이다. `sample`은 최대 500개의 P1 연결 검증기이며 대량 수집기의 중단 재개·shard 저장을 구현한 것이 아니다.
- 환경: Windows 11 10.0.26200, uv 0.13.6, CPython 3.12.16, Rasterio 1.5.2 / GDAL 3.12.2, NumPy 2.5.4, Pillow 12.3.0, PyProj 3.8.0, pystac-client 0.9.1, Shapely 2.2.0.
- 물리 RAM 약 34.28GB, 확인 시 가용 RAM 약 17.50GB, D 드라이브 가용 약 318.01GB다. 프로세스 최고 RAM 사용량은 계측하지 않았다.
- 샌드박스의 기본 uv 캐시·Python 링크 및 pytest 임시 경로 쓰기 제한이 있어 캐시와 Python 설치 파일은 `.local/`, 테스트 임시 파일은 `--basetemp .local/...`로 두었다. uv의 Python minor-version 링크 생성은 실패했지만 내려받은 실행 파일을 `uv sync --python`에 지정해 환경을 만들었고 이후 `uv run`이 동작했다. 전역 Python/PATH를 변경하지 않았다.

## 실행과 결과

다음은 실제 실행한 주요 명령이다. uv의 Python 설치 위치는 이 머신에서 `.local/uv-python`으로 지정했다.

```text
uv sync --python .local/uv-python/cpython-3.12.16-windows-x86_64-none/python.exe
uv run badapple-earth probe --input input/badapple.mp4 --output data/p1-input
uv run badapple-earth sample --config config/p1.json --output data/p1-sample-v2 --limit 120
uv run badapple-earth verify-sample --sample data/p1-sample-v2
uv run pytest -q --basetemp .local/pytest-p1-final
```

### 입력 영상

`input/badapple.mp4`는 33,253,859 bytes이며 Git에서 제외된다. ffprobe 결과는 H.264 1444×1080, SAR 1:1, DAR 361:270, 30000/1001fps, 영상 길이 약 232.065초, 컨테이너 길이 약 232.130초다. AAC 44.1kHz 스테레오 오디오가 있다.

전체 구간의 대표 프레임 12개와 38–48초의 2초 간격 미리보기를 확인했다. 일관된 레터박스를 제거할 근거가 없어 전체 프레임을 보존하고 38초부터 10초를 비교 구간으로 골랐다. `config/targets.json`에 고정했다. 미리보기의 seek 시각은 정확한 타깃 선택 PTS가 아니며, 60개 목표 프레임 추출은 P3에서 구현한다. 원본은 수정하지 않았고 오디오 사용권은 미확인이다.

### 실제 지리 이미지

`sentinel-2-c1-l2a`의 익명 HTTPS `visual`과 `scl`을 사용했다. SCL은 RGB 격자에 nearest-neighbor로 정렬하고, 모든 RGB 밴드 mask와 SCL 결함·구름을 확인해 후보를 보관했다. 원본을 칠하거나 실루엣을 합성하지 않았다.

| AOI | 보관 | 검사한 창 | 제외 사유별 수 |
| --- | ---: | ---: | --- |
| coast-kr | 40 | 63 | 부분 결측 22, 구름 5 |
| desert-na | 40 | 40 | 없음 |
| agriculture-us | 40 | 42 | 부분 결측 2 |

제외 사유는 한 창에 중복될 수 있다. 총 4개 장면, 120개 후보이며 256/512/1024px 폭별 수는 45/40/35개다. 수집 실행은 약 76.1초였고 샘플 디렉터리는 확인 시 약 10.48MB였다. 이는 대량 수집의 처리량·네트워크 비용 추정치가 아니다. 내부 요청 수·수신 바이트는 계측하지 않았다.

첫 실행 `data/p1-sample/`에서는 80/120개만 확보했다. 해안 AOI의 좁은 가장자리와 겹치는 장면을 선택해 결측에서 모두 제외됐다. 이를 성공으로 표시하지 않았으며, 장면의 실제 footprint와 AOI 겹침을 우선하고 footprint 밖 중심점을 건너뛰도록 수정했다. 두 번째 실행 `data/p1-sample-v2/`에서 120개를 확보했다. 장면별 시도 예산을 나누어 한 장면이 전체 예산을 소모하지 않게 했다.

모든 후보의 비교 시트를 보고 실제 해안·갯벌·사막·농경지·도시 주변 패턴이 있는지 확인했다. 동일 중심의 여러 스케일과 일부 날짜 중복도 포함한 접근 검증 표본이므로 지형 다양성이나 매칭 성과를 입증하지 않는다. 원본 창의 정수 반올림 때문에 미리보기 높이는 191/192px로 다르다. P2 특징 인덱스에서는 고정 콘텐츠 비율에 따른 하나의 공통 출력 shape를 사용해야 한다.

당시 수행한 대표 재추출 12개는 원본 RGB checksum·PNG 픽셀·캐시 checksum·안정 ID·품질 상태가 모두 일치했다. 세 AOI의 자산에 대한 별도 16-byte range 요청은 HTTP 206이었다. 이 확인을 정규 실행마다 반복하는 절차로 추가하지 않는다.

오프라인 테스트는 12개 통과했다. 회전 affine의 창 중심/footprint, UTM 좌표 순서, SCL 정렬, 유효 지형 보존과 결측/구름 제외, 원본 창 추출, AOI/footprint 범위, 타일 ID, 서명/비승인 자산 거절, 소량 상한·과금 정책을 확인했다. 마지막에 추가한 디스크 여유 확인은 별도 재실행하지 않았다. 네트워크 실행은 기본 pytest에 포함하지 않는다.

## 증거와 다음 작업

로컬 증거는 Git에서 제외된 다음 경로에 있다.

- `data/p1-input/`: `probe.json`, `environment.json`, 대표 프레임과 구간 미리보기.
- `data/p1-sample-v2/`: 실제 PNG 120개, `manifest.json`, `contact-sheet.jpg`, `verification.json`, `http-range-check.json`.
- `data/p1-sample/`: 첫 실행의 부분 성공 결과와 제외 사유.

원문 보관본은 수정하지 않았다. P2에서 기존 소스·좌표·품질 코드를 활용해 블록 기반 수집·고정 shape 특징·불변 shard·SQLite 작업 상태를 구현하고 1만 후보를 첫 체크포인트로 만든다. P3 검색·렌더를 구현하기 전에는 기술적 전체 파이프라인 성공이나 작품 품질을 주장하지 않는다.
