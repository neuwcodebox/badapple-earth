# P6 — 25개 Astra 서브에이전트의 전곡 연속 선택

## 채택과 실행 범위

관련 요구·단계는 F1·F6–F11·F14, N1–N7, P6이다. 사용자가 300프레임의 연속 선택 비교를 채택하고 최대 25개 서브에이전트로 전곡 제작을 요청했다. 기존 100만 실제 장소·400만 회전 view의 32×24 MSE Top-20과 사용자 보유 MP4의 6,955프레임 전체를 재사용했다. 검색·데이터 수집·MS-SSIM 점수 계산을 반복하지 않았다.

처음 다섯 job은 279프레임, 나머지 스무 job은 278프레임의 연속 구간이다. 뒤 구간에는 앞 10프레임을 참고 시트로 제공하되 출력에는 넣지 않았다. 각 후보의 local P ID는 섞고 exact view의 V ID는 전곡에서 고정했다. 기존 순위·점수·선택은 가렸다. 최대 동시 실행은 Astra 25개이며 `low` reasoning으로 원본·후보 20장을 시간순으로 보고 선택 ID만 저장하게 했다. 지침은 `config/astra-reviewer.txt`, 실제 job·시트·응답은 `data/reviews/astra-sequential-full/`에 남겼다.

시트가 준비된 구간부터 선택을 시작해 준비와 판단을 겹쳤다. 한 작업이 20개 저장 후 중단되어 같은 작업에 추가 지시 한 번으로 나머지 258개를 이어갔고 완료 판단을 다시 보지 않았다. 한 작업의 178개 응답은 `candidate_id` 대신 `choice` 키를 사용해 원본을 `raw-choices/`에 보관한 뒤 키 이름만 바꿨다. 선택 내용은 바꾸지 않았다. 이 형식 차이로 중단된 사진 준비도 저장된 캐시에서 재개했다.

## 제작 연동

`production.visual collect`로 전체 선택을 source PTS 순서의 Parquet에 연결했다. `assets.astra_choices`는 실험·target/index/search ID·모든 source slot·제시 후보 소속을 입력 계약으로 사용하며, 모델 선택을 다른 지표의 최대 후보로 다시 고르지 않는다. 표시 점수는 이전 전곡의 MS-SSIM을 참고용으로만 읽고 `score_role: reference`로 남긴다. Astra 자체의 수치 점수를 만들지 않았다.

기본 `config/production.json`은 Astra 선택을 사용하며 이전 설정은 `config/production-ms-ssim.json`으로 보존한다. 실제 선택과 MSE 상위의 다른 네 장소를 원래 검색 순위로 표시하고 선택 방향·위치에 연결선을 강조한다. 원본·세로 후보·큰 사진·카운터·참고 점수·좌표·촬영일의 기존 레이아웃을 유지했다. 원본 오디오를 로컬에서 전체 복사하고 프레임 생략·보간·크로스페이드·사진 합성을 사용하지 않았다.

준비한 canonical 사진은 고유 17,753 view이며 기존 PNG 6,961개와 로컬 RGB의 10,792개를 사용했다. 제작 화면은 고유 5,742개 후보 view를 표시한다. 최종 선택은 1,105개 실제 장소·1,210개 view다. 준비된 선택의 native 사진도 다른 구간의 모델 판단과 겹쳐 읽었다. 새 269개 view의 native 저장이 정상 완료됐고 fallback은 없었다. 최종 선택 중 native PNG가 있는 view는 521개이며, 작은 원본 창의 canonical 사진도 정상 출력이다. 정상 다운로드를 확인하려고 다시 읽지 않았다.

| 전곡 지표 | 기존 MS-SSIM | Astra 연속 선택 |

| 한 프레임 A→B→A 왕복 | 60 | 12 |
| 같은 view의 최장 유지 | 204프레임 | 204프레임 |

MS-SSIM과 다른 선택은 5,972프레임이다. 참고 MS-SSIM 평균은 Astra 선택 .46011094, 기존 최대 선택 .55565194다. 모델의 목적은 이 점수 최대화가 아니며 전환 감소나 숫자만으로 전체 형태 대응의 우월성을 주장하지 않는다. 300프레임은 사용자 재생 평가를 받았고 이번 전곡 전체의 재생 평가는 아직 수행하지 않았다. 앞 10프레임 참고만으로 24개 병렬 경계에서 실제 최종 선택이 같아지는 것도 보장하지 않는다.

- 전곡 시트 준비: 439.478초. decoded RGB bounded 캐시·네 스레드를 사용했다.
- 마지막 job 전달부터 모든 완료 응답까지의 관측: 약 1,284초. 첫 job들은 먼저 시작했고 조율·한 번의 재개 시간이 포함돼 순수 모델 처리 시간은 아니다.
- 최종 제작 파이프라인: 218.751초. 앞서 병렬 준비한 사진의 시간은 별도이며 모델·준비·제작 시간을 합쳐 단순 총시간으로 사용하지 않는다.
- 유료 API 호출은 0회다. 정확한 구독 사용량·모델 토큰 비용은 이 실행에서 제공되지 않았다.
