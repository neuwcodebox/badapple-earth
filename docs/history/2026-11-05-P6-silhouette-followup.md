# 큰 형태와 작고 복잡한 형태의 두 구간 비교

관련 요구·단계는 F5–F9, F11–F13, N1–N7, P5–P6다. 사용자는 첫 38–48초 결과가 더 나아 보일 수 있다고 평가했고, 서로 다른 형태의 10초 두 구간을 기존 방식과 새 윤곽 방식으로 크게 비교하도록 요청했다. 영상 자르기·전곡 적용은 이번 범위에 포함하지 않는다.

## 비교 조건

- 검색 결과를 보기 전에 원본의 32×24 소수 클래스 mask로 구간을 고른다. 10초 창을 5초 간격으로 훑되 처음 10초, 이전 38–48초와 겹치는 창, 218.5초 이후는 제외한다. 큰 형태는 비단색 비중 95% 초과 창 중 중앙 면적×최대 연결 성분 비중이 최대인 창, 작고 복잡한 형태는 중앙 면적 .035–.20·비단색 비중 90% 초과 창 중 중앙 `경계 길이/√면적`이 최대인 창이다. 검정/흰 배경에 대칭으로 소수 클래스를 사용한다.
- **작고 복잡한 형태 135–145초:** 300프레임, 소수 면적 중앙값 .16797, 최대 연결 성분 비중 중앙값 .67778, 복잡도 중앙값 7.36111이다.
- **큰 형태 205–215초:** 300프레임, 소수 면적 중앙값 .48698, 최대 연결 성분 비중 중앙값 .90539, 복잡도 중앙값 5.05716이다. 선택한 원본의 0/3/6/9초 정지 화면을 확인했다. 큰 형태 창에도 전환과 작은 형태가 섞이므로 모든 프레임이 같은 유형이라는 뜻은 아니다.
- 설정은 `config/silhouette-followup.json`, 출력은 `data/runs/p6-silhouette-followup-20s/`다. 선택 과정의 수치와 전체 창은 `.local/silhouette-interval-selection.json`, 시트는 같은 접두사의 PNG, 실행기는 `.local/run_silhouette_followup.py`다.
- 두 구간의 600프레임을 묶어 전체 120만 장소·2,880만 view를 한 번 순회한다. 최초 실험과 동일한 두 Top-512·MSE Top-20 합집합과 .35/.35/.30 가중치·시인성 조건을 유지한다. 기존 MSE→MS-SSIM 선택을 그대로 대조군으로 둔다. 두 방식의 후보 폭 차이도 유지되므로 평가식만의 효과를 분리한 비교는 아니다.
- 각 영상은 왼쪽 현재 방식·오른쪽 윤곽+실제 대비·위쪽 작은 원본이며, 원색 RGB와 회전/크롭·출처를 보존한다. 영역 균형 선택도 기록하되 화면은 두 방식에 집중한다. 구간별 교체 횟수와 fallback을 기록한다.

## 실행·검증 상태

- `tests/test_visible_silhouette.py` **17개 통과**. 기존 점수·실제 view 대응 외에 비연속 구간의 원래 PTS와 끝 경계 제외, 겹침·음수·빈 구간·경로 이름·크레딧 이후 거부, 임의 주소와 밀집 동률의 Top-K 전수 정렬 일치를 검증했다.
- 최초 검색 중 후보 Top-K가 병목임을 확인했다. 기존 상관 검색의 Numba 병렬 삽입 방식을 사용하도록 바꿔 점수와 전역 주소 정렬을 유지했다. 64×8,192·K512의 로컬 비교에서 NumPy와 기존 Numba 방식 결과가 정확히 같았고, 10회 평균은 초기 .01390→.00845초, 후기 .01401→.00233초였다. 전수 정렬 계약을 추가 검증한 뒤 이미 처리한 체크포인트부터 재개했다.
- 타깃 특징 LRU를 384→1,024개로 늘려 600개 질의가 RGB 작업자 안에서 퇴출·재계산되지 않게 했다. 기존 사진과 metric은 바꾸지 않았다.
- 실행은 20:38경 시작했으며 최초 완료 예상은 21:15–21:30 KST다. 현재 실행 중으로, 영상 생성·실제 선택·사용자 재생 평가는 아직 완료로 표시하지 않는다.
