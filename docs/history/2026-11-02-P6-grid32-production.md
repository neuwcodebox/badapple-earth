# P6 — 32×24 Top-20 채택과 전곡 제작

## 결정과 범위

사용자는 격자/후보 비교에서 32×24 Top-20을 선호했다. 이를 기본 제작으로 채택하고 기존 전곡 제작 요청의 모든 원본 프레임·원본 오디오·간결한 16:9 설명 화면을 유지한다. 32×24가 모든 구간에서 반드시 낫다고 가정하지 않는다. 기존 전곡·비교 결과는 보존한다. 관련 요구는 F1·F5–F9·F11·F14·N1–N7이다.

기본은 32×24 MSE Top-20 **view 전체**를 256×191 MS-SSIM으로 평가한다. 표시할 다섯 장소를 먼저 골라 평가를 제한하지 않는다. 실제 선택과 MSE 상위의 다른 네 장소를 선택 뒤에 정하고 원래 MSE 순위를 표시한다. 같은 장소의 앞선 회전으로 선택된 방향을 바꾸지 않는다. 표시 위치와 검색 순위를 구분하며 강조선은 실제 선택을 따른다.

## 구현과 검증

`production/grid/search.production_search()`가 단일 fine-grid 전수 검색을 수행한다. 기존 단위 검증한 정확 float64 BLAS·정수 SSE·view ID 동률·후보 스트리밍을 재사용한다. fine 원배열이 동일할 때만 검색 계산을 공유하고 모든 실제 source frame을 복원한다. `reuse_run`의 격자나 K가 다르면 검색을 복사하지 않으며 타깃·사진은 재사용한다.

전체 20개 평가는 MS-SSIM 전용 RGB 배치 평가기를 재사용한다. 같은 타깃·인덱스·MS-SSIM 버전의 점수만 재사용한다. 모든 평가가 끝난 뒤 화면에 필요한 PNG를 만들고, 큰 원본 창에서 새로 선택된 사진에 필요한 native 픽셀만 추가 읽는다. 이미 있는 native PNG는 다시 요청하지 않는다.

캐시 사진 준비 함수를 `production/assets.py`로 모아 비교와 전곡이 같은 bulk RGB 행 읽기를 사용한다. 후보 숫자는 표시 순번 대신 실제 MSE 검색 순위다. `config/production.json`의 기본은 `search_grid=fine`, `top_k=20`, `rerank_top_k=20`, `display_top_k=5`다. 선택된 사진·후보·점수·실제 PTS·촬영/좌표·회전은 출력 테이블로 연결한다.

초기 관련 테스트 7개가 12.34초에 통과했다. 20개 후보에서 고른 회전이 표시에서 보존되는지, 서로 다른 다섯 장소와 원래 순위가 유지되는지, 격자가 다른 검색을 잘못 재사용하지 않는지 확인했다. 기존 전체 source PTS·입력 변경 거부·원래 fps와 segment 재개, 정확 MSE와 후보 폭 선택 계약도 확인했다. 느린 전체 테스트나 다운로드 확인은 하지 않았다.

## 실제 실행과 결과

`data/runs/p6-grid32-full/`에서 32×24 전곡 검색을 완료했다. 실제 6,955프레임을 6,423개 fine 검색 질의로 계산 공유했으며 출력 프레임은 생략하지 않는다. 검색 시간은 289.315초로 점수 평가·출처 해석·사진·렌더링은 제외한다. 출처 15,199개를 재사용했다. 검색 run ID는 `1100648c82ff321806ea8dd90df6c1ae57bc4ff05fcb5aa05e5106b1afb4aa54`다.

원본 MP4와 타깃은 이전 전곡에서 그대로 재사용하며 target ID는 `6ed26d6e41b9fb13c45f6c2222ed659d93e574a4d95b856fd3b8d0e9946d969f`, index ID는 `0af3913546907b7000fc31ce96d5a659e23f9492856ba7eeae11ea9715e12a6f`다. 원본 6,955×20=139,100쌍 가운데 이전 같은 구간의 6,000쌍을 재사용하고 133,100쌍을 새로 계산했다.

생산 ID는 `ea1c7d0ff2d57ca9aca676cd41088be2b92afe1330165984614f4256198d7f15`, render ID는 `ad25b6716f4b128b5e0874e83b8fdacf2d46e759cfda27eacd62787119a15105`다. 선택은 1,246개 장소·1,499개 view, 평가한 고유 view는 17,753개다. 표시용 5,896개 view만 PNG로 준비했다. 선택된 677개 view에 native PNG가 있으며 이번에 새로 읽은 314개는 모두 성공했다. 나머지 큰 사진은 기존 캐시를 재사용했고 실패 대체는 없었다. canonical 사진 재다운로드나 SCL 재확인은 하지 않았다.

전곡의 평균 선택 MS-SSIM은 .555652다. 이전 10초 구간의 평균과 모집단이 다르므로 직접 비교하지 않는다. 원래 MSE 순위 1–20이 모두 최종 선택에 사용됐다. 표시 위치 1–5의 선택 프레임 수는 1,288·902·490·593·3,682다. 후보 위치를 임의로 바꾸거나 다양한 줄에 연결하기 위한 페널티는 없다. 대표 41초 화면은 실제 MSE 8위가 다섯 번째 표시 위치에서 선택된다.

점수 평가·취합은 152.759초, 이전 검색을 재사용한 이후의 전체 생산은 464.352초다. 별도 선행 검색 289.315초와 합치면 계측된 실행은 약 12분 34초다. 구현 시간과 두 단계 사이 대기는 포함하지 않는다. 선택된 새 사진의 큰 화면용 원본 픽셀만 추가 읽었으며 네트워크 바이트는 별도 계측하지 않았다.

두 영상은 원본 AAC의 9,997프레임·232.129887초를 그대로 유지한다. 원본에 있던 약 65ms의 오디오 꼬리 때문에 영상 프레임을 추가하지 않았다. 두 파일의 ffprobe 메타데이터를 한 번씩 확인하고 실제 대표 화면을 열어 숫자·선택선·원색 사진·좌표가 표시되는지 확인했다.

전곡 selected/frame-plan의 6,955개 순서와 source PTS가 원래 타깃과 모두 같았다. 모든 프레임에서 표시 장소가 정확히 다섯 개로 서로 다르고, 강조된 view·점수가 실제 최종 선택과 같았다. 이전 격자 비교의 `32-20` 조건 300프레임도 같은 view를 선택했다. 재사용 설정의 K 변경도 검색을 잘못 복사하지 않는지 확인한 마지막 캐시 테스트 3개는 1.30초에 통과했다. 새 전체 테스트나 수신 확인용 다운로드는 하지 않았다.

`candidates.parquet` 17,753행은 고유 view의 실제 출처만 담으며 질의별 rank/SSE는 `search/matches.parquet`와 연결한다. `evaluations.parquet` 139,100행과 지표 버전·타깃/인덱스 ID를 남겨 다음 실험의 점수 캐시로 쓸 수 있다. `selected.parquet`·`frame-plan.parquet`는 각 6,955행이며 실제 source PTS·회전·출처·선택·표시 순위를 담는다. 제작은 완료했지만 전체 주관적 재생 평가와 외부 공개 업로드는 하지 않았다.
