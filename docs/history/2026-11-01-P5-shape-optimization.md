# P5 — 실제 형태 검색의 병목 최적화

- 관련 요구: F5–F10, F13, N1–N3, N6.
- 사용자 요청: 느린 정밀 실행의 최적화를 먼저 수행하고 [최적화 참고 문서](Bad_Apple_Shape_Optimization.original.md)를 참고한다. 문서의 독립 참고 코드·합성 성능 수치를 실제 프로젝트 측정으로 취급하지 않는다.
- 상태: 최적화 구현·필요한 동치 확인 후 같은 10초 실행과 출력을 완료했다. 전체 결과는 [형태 검색 실행 기록](2026-11-01-P5-shape-v2.md)에 둔다.

## 실제 병목과 변경

21프레임의 완료 JSON 공개 후 해당 검색의 부모·작업 프로세스만 멈췄다. 10만 분석 캐시와 완료 점수는 보존했다. 실제 첫 타깃의 coarse 후보 64개·fine 후보 16개를 조사하니 프로파일 6.01초 중 SciPy EDT가 누적 약 2.99초, Parquet 행 해석 약 0.76초였고 경계 준비·방향성 비교도 컸다.

- 이미지 접근에서 Parquet 재해석을 제거하고 base-major 0/90/180/270 행 배치로 공유 RGB를 참조한다. 후보 계산 순서를 물리 shard·행으로 묶는다.
- 두 클래스의 정확한 EDT 열 패스를 합치고 행의 제곱거리 포물선 포락선을 Numba로 계산한다. 포화 거리의 제곱근을 생략한다. 36개 격자·밀도·공집합/전체집합 사례에서 기존 float32 SDF와 배열이 같았다. OpenCV precise EDT도 비교했으나 최종 의존성에는 남기지 않았다.
- 기존에도 Chamfer는 cap 반경과 전역 최소 각도 항으로 정확히 분해했다. 참고 문서의 정수 격자·거리순 offset·공간 하한 조기 종료를 적용해 트리·희소 행렬 생성을 제거했다. 기존 float32 각도·연산 순서와 평균 순서를 유지한다.
- 동일 실제 packed mask·shape·규칙으로 SDF/윤곽을 재사용하고 worker당 payload 128MiB로 제한한다. 임곗값 순서 제약 DP의 낙관적 하한을 해결해 필요한 Chamfer만 계산하며 모든 후보의 정확한 최소 점수와 +0.01 선택 집합을 유지한다.
- 각도 계산은 경계점에서만 수행한다. BLAS·Arrow의 내부 병렬화를 제한하고 지속적인 8개 작업 프로세스로 처리한다. Numba fastmath·방향 bin 근사·해상도·후보 K 축소는 사용하지 않는다.

## 측정 범위와 동치

같은 실제 후보 64 coarse·16 fine, 초기화된 마스크 캐시에서 기존 구현 약 5.78초→최적화 약 2.65초로 약 2.18배였다. JIT 초기 컴파일은 제외했고 로컬 RGB 접근과 실제 점수 계산은 포함했다. 점수 성분·선택 임곗값·출력 픽셀은 같았다. 이 표본에서는 2,880회 캐시 요청이 모두 미스였고 480개 Chamfer를 모두 계산했다. 캐시나 하한 가지치기로 얻은 가속처럼 보고하지 않는다. 이후 경계 각도 계산과 Arrow 스레드 제한을 더 줄였다.

두 실제 새 프레임의 전체 처리시간은 19.44초·13.88초였다. 첫 프레임은 worker 시작 비용도 포함한다. 기존 첫 21개의 fine 완료 파일 간격 중앙값은 약 49.14초였다. 프레임이 다르므로 이 둘의 비를 동일 입력의 보장된 가속 배수라고 부르지 않는다. 완료 JSON의 mtime은 backend 주석 갱신으로 달라졌으므로 이전 간격은 변경하지 않은 fine JSON을 기준으로 측정했다.

마지막 재개의 37프레임은 총 320.66초·중앙값 5.344초였다. 회색 레벨 수와 형상 복잡도가 달라 초기 프레임과 단순 비율로 비교하지 않는다. 최적화된 39개 타깃의 fine 후보 12,638개에서 Chamfer는 가능한 160,406개 중 160,274개를 계산했고 마스크 캐시 hit/miss는 10,749/309,931이었다. 이 workload의 fine 하한 생략·캐시 효과는 작았으며 큰 가속처럼 부풀리지 않는다. 전체 점수·영상 출력까지 완료했다.

필요 계약 테스트는 7개다. 정확 EDT의 빈/전체·가장자리·무작위 격자 동치, 공간/방향 joint minimum, 원래 색상과 모든 방향 픽셀의 동일성, byte 예산·마스크 격자 구분, 분할 Top-K·전체 파이프라인 재개를 확인했다. 전체 프로젝트 suite나 원본 다운로드 확인은 반복하지 않았다. 벤치마크 상세는 로컬 `.local/shape-optimization-benchmark.json`에 남기며 전체 영상 결과로 대체하지 않는다.

## 참고 문서와 질의 회전

참고 문서의 모든 수치를 그대로 채택하지 않았다. 현재 코드는 이미 전수 점쌍 대신 반경을 이용했으므로 예제의 전수 점쌍 대비 가속 배수를 적용할 수 없다. 실제 첫 타깃의 region 하한 표본에서는 coarse cutoff로 생략 가능한 후보가 없었고 뒤 타깃에서는 약 절반이었다. 현재는 후보를 더 줄이는 전역 가지치기 대신 임곗값 경로의 정확한 하한만 적용한다.

사용자의 질의 회전 아이디어는 가능하다. 다만 기존 저장 특징 1,000개에서 180도 단순 배열 반전과 실제 재추출 특징의 최대 차이가 Rank 약 0.353·PHOG 약 0.026이었고, 90/270도는 중앙 크롭의 정수 반올림도 달랐다. 이 수치는 형상 성능 평가가 아니라 기존 특징을 그대로 재배열해 같은 결과라고 주장할 수 없다는 근거다. 현재 RGB는 이미 장소당 한 장을 공유하며, 이번 실행은 기존 화각·점수·완료 체크포인트를 유지한다. 질의 회전 전환 시에는 화각·리사이즈·격자·최종 역회전을 함께 버전 관리한다.
