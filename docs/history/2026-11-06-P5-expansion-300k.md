# P5 — 네 소스에서 실제 항공사진 30만 후보 추가

관련 요구: F2–F5, F7, F10–F13, N1–N4, N6. 사용자가 [데이터원 조사](2026-11-06-P5-data-source-research.md)의 확대 제안을 승인했다. 기존 120만 후보와 영상은 보존하고 별도 인덱스에 추가 수집한다. 30만은 자원 계측 중간 지점이며 최종 상한이 아니다.

## 구성과 자원

| 설정 | 추가 목표 | 탐색 범위 | 원본 창 폭 |
| --- | ---: | --- | --- |
| `config/collect-expand-naip.json` | 100,000 | 기존 36개 AOI와 겹치지 않는 미국 48개 AOI·6개 탐색 지형군 | 256/512/1024/2048px |
| `config/collect-expand-linz.json` | 100,000 | 25개 미수집 도시 촬영 사업, 지역별 최대 두 사업 | 512/1024/2048/4096px |
| `config/collect-expand-netherlands.json` | 50,000 | 2025년 25cm RGB, 16개 AOI | 256/512/1024/2048px |
| `config/collect-expand-swiss.json` | 50,000 | 2022–2026년 대표 연도, 16개 AOI·10cm 배포 RGB | 512/1024/2048/4096px |

지형군은 탐색·할당 분류이며 실제 토지피복 라벨이 아니다. LINZ는 공개 root의 2022년 이후 도시 사업에서 같은 이름의 최신 사업을 우선하고 region별 최대 두 곳을 고른 고정 목록이다. 촬영 사업·지역·창의 실제 분포는 각 manifest에 남긴다. 다른 촬영 사업의 같은 물리적 지역을 모두 새로운 지리 장소로 해석하지 않는다.

소스별 두 writer를 사용하며 NAIP·LINZ, 네덜란드·스위스 순으로 두 소스씩 실행한다. 네덜란드·스위스의 초기 실제 수집 검증만 첫 단계 중 각각 한 블록을 순차 실행했다. 각 writer의 메모리 상한은 3GiB, 디스크 예산은 약 17.6GiB, 공유 여유 공간 하한은 30GiB다. 시작 전 여유는 약 157.5GiB였다. RGB만 약 41GiB, 특징·메타데이터·일시 블록·후속 검색 저장은 별도다. 전체 전국 원본 다운로드·사용자 키·Requester Pays·유료 서비스·클라우드 실행은 사용하지 않는다.

## 구현과 출처 계약

`sources/europe.py`가 스위스 STAC와 네덜란드 공식 다운로드 색인을 기존 수집기에 연결한다. 승인된 HTTPS 호스트·상품 경로의 무서명 GeoTIFF만 읽고 RGB 1/2/3과 dataset mask를 사용한다. 구름 품질은 미평가이며 원본 RGB는 BOX 축소만 해 보관한다. 기존 shard·RGB 캐시·직각 회전 특징·재개·자원 검사를 재사용한다.

네덜란드 geometry의 EPSG:28992를 경위도로 변환하고 색인의 파일 SHA-256·mtime·URL을 보존한다. SHA-256은 공급자 값이며 전체 원본 파일을 다운로드해 검증한 해시가 아니다. 네덜란드는 `product_year`, 스위스는 `nominal_tile_year`로 촬영 정확도를 보존하고 `acquired_at=YYYY`로 저장한다. 스위스 원본 timestamp와 라이선스·혼합 출처 고지도 별도로 남긴다. 파일 mtime이나 1월 1일을 실제 촬영일로 표시하지 않는다. 새 소스를 Sentinel-2로 오인하는 크레딧을 방지하고 날짜 표시에서 대표/제품 연도를 구분한다.

항공사진의 4096px 창은 초고해상도 도시 자료의 지상 폭을 넓히기 위한 것이다. Sentinel-2·P1의 2048px 한도는 유지한다. 실제 block+halo 예상 메모리가 예산을 넘으면 저장된 데이터와 체크포인트를 보존하고 중단한다.

## 검증과 실제 실행

- 새 소스 정규화·좌표계·연도 정확도·공개 URL 경계·크레딧·4096px 한도와 기존 수집·병렬·중간 스냅샷·매칭·제작의 영향 범위 오프라인 테스트 **39개가 통과**했다. `uv run pytest tests/test_european_sources.py tests/test_aerial_collection.py tests/test_collection.py tests/test_parallel_collection.py tests/test_incremental_collection.py tests/test_matching.py tests/test_production.py -q --basetemp .local/pytest-expansion-contracts-20261106`으로 실행했다. 더미 영상은 테스트에만 사용했고 실제 성과로 보고하지 않는다.
- 네덜란드·스위스는 최종 병렬 작업과 동일한 part 설정·quota로 한 블록씩 먼저 수집했다. **네덜란드 313개·스위스 120개를 저장**하고 `paused`로 종료했다. 이 데이터와 카탈로그를 후속 실제 수집에서 재사용한다. 더미 성과가 아니다.
- NAIP·LINZ는 **2026-11-06 20:31 KST**에 실제 병렬 수집을 시작했다. 진행 중 행 수·완료 상태는 로컬 제어기와 각 part manifest·로그를 기준으로 한다. 초기 상태에서 네덜란드·스위스 part-01은 검증을 마친 `paused`이며 첫 두 소스 종료 후 자동으로 이어간다.
- 생성 경로는 `data/index/p5-expand-{naip,linz}-100k/`, `data/index/p5-expand-{netherlands,swiss}-50k/`다. 실제 랜덤 표본은 각 part의 `contact-sheet.jpg`, 출처·창·정확도는 shard의 `tiles.parquet`와 `catalog/`에 있다.
- **20:38 KST 진행 관측:** NAIP 3,347개·LINZ 1,687개·네덜란드 313개·스위스 120개, 합계 **5,467개**를 공개 shard에 저장했다. 장면 실패 기록은 0개, 작업별 관측 peak RSS 최대 약 395MiB, 드라이브 여유 약 155.2GiB다. 수집 중 스냅샷이며 최종 수량·자원 사용이 아니다. 첫 shard의 저장 RGB로 만든 `data/access-check/expansion-2026-11-06/collection-preview.jpg`에서 네 소스의 실제 사진·화각을 확인했다. 같은 지리 블록 안의 예시이며 무작위 전체 표본이나 매칭 성공 증거가 아니다.

## 실행·재개

공식 CLI는 소스마다 같은 설정·출력·목표·작업 수로 재개한다.

```powershell
uv run badapple-earth collect-parallel --config config/collect-expand-naip.json --output data/index/p5-expand-naip-100k --limit 100000 --workers 2
uv run badapple-earth collect-parallel --config config/collect-expand-linz.json --output data/index/p5-expand-linz-100k --limit 100000 --workers 2
uv run badapple-earth collect-parallel --config config/collect-expand-netherlands.json --output data/index/p5-expand-netherlands-50k --limit 50000 --workers 2
uv run badapple-earth collect-parallel --config config/collect-expand-swiss.json --output data/index/p5-expand-swiss-50k --limit 50000 --workers 2
```

현재 로컬 제어기는 `uv run python .local/run_expansion_20261106.py`이며 상태는 `.local/expansion-20261106.json`, 소스 로그는 `.local/expansion-{source}.log`다. 같은 writer에 중복 실행하지 않는다. 정상 완료한 데이터는 확인 목적으로 다시 받지 않는다. 제어기·준비 스크립트·생성 데이터는 Git에서 제외하고 정규 adapter·설정·테스트·문서는 추적한다.

네 소스가 실제 목표·종료 코드 0으로 완료되면 기존 `data/index/p5-aerial-1.2m`과 여덟 part의 manifest·수량을 합해 `data/index/p5-aerial-1.5m`에 참조 결합한다. 정규 CLI는 `combine --keep-duplicates`, 로컬 제어기는 같은 `concatenate` 함수를 사용한다. 전체 타일 표를 다시 읽거나 별도 인덱스의 중복 사진을 제거하지 않는다. `tile_deduplication=not_performed`를 기록하고 수량은 후보 항목 합계로 보고한다. 부분 수집을 완성된 150만으로 표시하지 않는다.

수집 중에도 유사 사진의 dHash·명암 비교를 수행하지 않는다. 재개할 때 완료한 창을 건너뛰는 SQLite·cursor 검사는 유지한다. 이 정책을 실행 중인 수집에도 적용하기 위해 **20:45 KST**에 제어기를 중단하고 기존 shard·블록 캐시·체크포인트에서 재개했다. 재개 후 같은 AOI에서 후보 수가 증가하는 것을 확인했다. 타일 표를 열지 않고 중복 ID를 그대로 보존하는 결합·기존 재개/저장 계약 테스트 **32개가 통과**했다.

이번 범위는 추가 수집과 재사용 인덱스 준비다. 취소된 이전 60타깃 규모 비교·기존 전곡 재검색·자동 업로드는 실행하지 않는다. 새 데이터의 실제 매칭·재생 개선은 미검증으로 남기고 다음 제작에서 같은 타깃·선택 조건으로 평가한다.
