# 형태 허용폭 안에서 색감이 이어지는 후보 선택

관련 요구·단계는 F5–F9, F11–F13, N1–N7, P5–P6다. 사용자가 형태는 읽히지만 프레임마다 색이 크게 바뀐다고 지적했다. 기존 Astra 연속 선택은 모델에게 앞 프레임을 참고시키는 방식이고, 새 독립 윤곽 선택에는 수치적인 색 연속성 항이 없었다. 새 모델 호출 없이 기존 계산 결과를 재사용하는 CPU 동적 계획법을 적용했다.

## 조건과 구현

- 입력은 완료한 `data/runs/p6-silhouette-followup-20s/`의 135–145초·205–215초, 원본 600프레임이다. 검색과 605,350쌍의 형태 점수·출처는 그대로 재사용한다.
- 시인성 통과 후보 중 프레임 최고 형태 점수에서 .02 이내인 최대 24개를 보관하며 원래 윤곽 승자를 포함한다. fallback은 원래 사진 한 장으로 제한한다. 실제 남은 후보는 **537개 고유 view·1,313개 프레임/view 쌍**이다. 후보가 부족한 프레임에서는 색을 더 맞출 수 있는 선택 폭도 제한된다.
- 실제 변환 사진을 64×48 YCbCr로 줄여 원본 흰/검정 영역별 평균과 6×6 CbCr 히스토그램을 구한다. 영역별 비중은 동일하고, 평균 Y의 민감도는 chroma의 .25다. 평균 부분의 제곱 거리 비중은 .2, 제곱근 히스토그램은 .8이다. 사진 자체 RGB는 바꾸지 않는다.
- 구간마다 `형태 점수 손실의 합 + .2*인접 색 거리의 합`을 최소화하는 경로를 동적 계획법으로 선택한다. 앞 프레임만 보고 고르는 탐욕법이 아니며 같은 view 유지 보너스·최소 유지 시간은 두지 않는다. .02 허용폭과 .2 가중치는 최초 실험값이다.
- `production/silhouette/temporal.py`와 `config/silhouette-color.json`이 구현·설정이다. 기존 두 화면 렌더러에 좌우 제목·왼쪽 점수 설명 인자를 추가해 잘못된 MS-SSIM 표시 없이 **왼쪽 독립 윤곽/오른쪽 색감 연속 선택/위쪽 원본**을 보여준다.

## 결과와 검증 범위

출력은 `data/runs/p6-silhouette-color-20s/small-complex.mp4`와 `large.mp4`다. 둘 다 렌더 입력 기준 1920×1080·300프레임·30000/1001fps·무음이다. 실행 **29.267초**, 21:27 KST 완료다. 색 특징 15개 배치를 저장했고 선택 사진은 기존 PNG 269개를 재사용하고 로컬 RGB에서 40개를 새로 출력했다. 새 전수 검색·형태 점수 재계산·원격 읽기는 **0건**이다.

| 구간 | 평균 색 변화량: 독립→연속 | 감소 | 사진 교체: 독립→연속 | 평균 형태 점수 손실 |
|---|---:|---:|---:|---:|
| 작고 복잡한 형태 | .161835→.101688 | 약 37% | 112→88 | .000964 |
| 큰 형태 | .279164→.191111 | 약 32% | 188→172 | .002269 |

색 변화량은 실제 선택에 사용한 descriptor의 인접 제곱 거리 평균이며 사람의 시각 평가를 대체하지 않는다. 형태 점수 손실도 인지 품질의 손실 비율로 바꾸지 않는다. 전곡 적용은 하지 않았으며 사용자의 재생 평가를 기다린다.

새 알고리즘의 빠른 오프라인 테스트 **4개 통과**: 형태 허용폭 밖 후보·기존 fallback 보존, 미래 프레임을 고려하는 선택과 가중치 0의 독립 선택, 작은 후보 집합의 전수 조합과 전역 최솟값 일치, 실루엣 면적이 바뀌어도 영역별 팔레트 동일·실제 색 변경 구분이다. 영역 평균의 float32 누적 오차가 면적에 따라 달라지는 문제는 float64 누적으로 수정했다. 테스트 합성 사진은 실제 성과로 집계하지 않는다. 기존 계약·다운로드·출처·좌표·시간축의 반복 검수와 전체 재생 검수는 하지 않았다.
