# 영역 균형·윤곽·실제 경계 대비의 10초 비교

관련 요구·단계는 F5–F9, F11–F13, N1–N7, P5–P6다. 사용자가 형태 우선 검색을 논의한 뒤 10초 비교를 요청했다. 잘라낼 끝 지점은 **3분 38.5초(218.5초)**로 확인했으나 사용자가 자르기는 나중에 하도록 지시해 중지했다. 이번 작업은 자르기를 재개하지 않는다.

## 비교 조건과 구현

- 구간은 이전 결과와 직접 대응하는 **38–48초·원본 300프레임**이다. 기준 run은 `data/runs/p6-aerial120-views30-full`이며 120만 장소·2,880만 view를 사용한다. 전체 MSE 검색 결과와 현재 MS-SSIM 선택은 유지한다.
- 새 검색은 영역 균형 MSE와 부호 있는 gradient correlation의 독립 두 경로다. 각 Top-512와 기존 MSE Top-20을 합쳐 고해상도 평가하므로 새 검색을 기존 MSE shortlist로 제한하지 않는다.
- 기존 32×24 특징만 스트리밍해 지역별 밝기 비교와 16/32 gradient 특징을 만든다. 사진의 원색을 바꾸거나 원본을 다시 받지 않는다. 특징 준비는 3개 스레드로 제한된 선행 계산을 하고 부모의 8 BLAS 스레드 검색과 겹친다. checkpoint 공개 순서는 고정돼 결과가 바뀌지 않는다. 동률은 고정 전역 dense 주소 순서다.
- 정밀 점수는 원색 사진의 64/128 폭에서 영역 균형 MSE·signed gradient correlation·경계 양쪽 실제 대비를 계산한다. 경계의 타깃 법선을 따라 반경 1/2/4px에서 흰/검정 위치가 실제로 갈라지는 쌍만 평가한다. 사진을 임계화해 가상 실루엣을 만드는 점수는 쓰지 않는다.
- 최초 합성 가중치는 영역 .35·윤곽 .35·경계 대비 .30이다. 실제 영역 대비 .08, 경계 대비 .08 이상인 점 50% 이상, 반대 극성 경계점 15% 이하, 양의 GC를 시인성 조건으로 둔다. 이 값은 최초 실험 설정이며 최적값이나 품질 보장이 아니다. 단색·통과 후보 없음은 현재 선택으로 되돌리고 사유를 기록한다.
- 출력은 원본·현재 MSE→MS-SSIM·영역 균형·형태와 실제 대비의 네 화면이며 전부 같은 원본 프레임이다. 실제 RGB 사진·회전/크롭·좌표·촬영 구간·출처를 보존한다. `config/silhouette.json`과 `production/silhouette/`가 설정·구현이다.

이전 10만 PHOG/Rank/SDF/Chamfer 형태 검색은 사용자 재생 평가에서 MSE보다 약했다. 이전 자체 형태 점수 상승을 재생 개선으로 취급하지 않으며, 이번 실험은 원색에서의 경계 대비를 직접 평가하는 별도 방법이다. 이전 상관 검색 구현과 RGB 읽기·캐시·변환·비교 레이아웃의 기존 확장점을 사용했다.

## 검증과 실제 결과

- `tests/test_visible_silhouette.py` **8개 통과**: 흑/백 각 .5의 영역 비중, 원색 대비가 약하지만 이진 mask는 동일한 사진의 시인성 거부, 명암 극성 반전 거부, 실제 승자/fallback 보존, float32 Top-K 경계 동률, 전수 가중 MSE 일치·질의 공유·검색 완료 재사용, 캐시 RGB의 직각·30° 크롭 변환과 정밀 점수 대응이다. 합성 자료는 테스트 전용이다. 최종 명령은 `uv run --no-sync pytest tests/test_visible_silhouette.py -q --basetemp .local/pytest-silhouette-final`이다. 기본 임시 디렉터리 접근 오류는 workspace 내 임시 경로로 해결했다.
- 기존 affine 지리 변환기를 CRS별로 bounded LRU 재사용하도록 해 새 후보 provenance 해석 비용을 줄였다. 새 점수와 기존 affine 계약의 영향 범위 **39개 통과**이며 변환 recipe나 실제 사진은 바꾸지 않았다.
- 실제 검색은 19:55경 시작해 체크포인트 재개를 포함한 계산 **976.727초**로 2,880만 view를 모두 검색했다. 20:12경 검색을 끝냈고, 메타데이터 및 RGB 정밀 평가 뒤 **20:30 이전에 영상 생성을 완료**했다. RGB 단계는 디스크 읽기 병목이어서 초기 예상보다 길어졌으며 최종 예상은 20:30–20:40 KST로 갱신했다.
- 정밀 평가는 **60,369개 고유 view·300,126개 프레임/view 쌍**이다. 메타데이터 20개 및 RGB 점수 396개 배치를 저장했다. 원격 읽기·추가 다운로드는 **0건**이다.

| 선택 | 기존과 다른 프레임 | 평균 영역 균형 MSE ↓ | 평균 경계 대비 충족률 ↑ | 장소 수 |
|---|---:|---:|---:|---:|
| 현재 MSE→MS-SSIM | 0 | 0.15313 | 50.03% | 81 |
| 영역 균형 | 269 | 0.08902 | 53.64% | 75 |
| 윤곽+실제 대비 | 227 | 0.13083 | 62.36% | 140 |

윤곽 방식은 시인성 통과 후보가 없는 **56프레임을 기존 선택으로 유지**했다. 이 구간에는 단색 fallback이 없었다. 위 지표는 선택에 사용한 자체 점수이며 인지 품질 개선의 증거로 해석하지 않는다. 현재 선택은 MSE Top-20이고 새 방식은 더 넓은 두 경로의 합집합이므로 검색 범위와 평가 방식이 함께 달라진 비교다. 점수 변경만의 효과를 분리한 실험은 아니다.

`comparison.mp4`는 **1920×1080·30000/1001fps·300프레임·10.01초·무음**이다. 전체 300프레임 디코딩, 세 방식의 선택 900행과 source PTS 일치, 현재 방식 300개의 기존 view ID 일치, 사진·좌표·실제 장면/촬영 시점·출처 연결을 확인했다. `verification.json`에 근거를 둔다. 고정 중간 프레임 `preview.png`를 확인했으며 해당 프레임의 윤곽 방식은 표시된 대로 기존 선택 fallback이다. **전체 동영상 재생과 사용자의 형태 인식 평가는 미실시**다.

실행 스크립트는 `.local/run_silhouette.py`, 로그는 `.local/silhouette-10s-resumed.log`다. 산출물은 `data/runs/p6-silhouette-visible-10s/`의 `comparison.mp4`, `preview.png`, `selected.parquet`, `credits.json`, `manifest.json`, `verification.json`이다. `retrieval.npz`, `progress.json`, metadata/score 배치도 보존한다. 취소된 수집 규모 비교·영상 자르기는 실행하지 않았다.
