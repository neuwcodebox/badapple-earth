# P6 — Astra의 연속 후보 선택과 병렬 구간 처리

## 범위와 설계

관련 요구·단계는 F6·F7·F9·F11, N1–N7, P6이다. 사용자가 독립 Astra 선택 영상의 깜빡임을 지적해, 같은 후보에서 이전 장면과 선택을 고려하는 연속 모드를 실행했다. 대상은 기존 38–48초의 모든 300프레임(source slot 1139–1438), 각 프레임의 32×24 MSE Top-20이다. 검색·후보·사진 색상·광도·회전은 바꾸지 않았다. 기본 전곡은 MS-SSIM을 유지한다.

연속 100프레임씩 `gpt-6-astra` 세 에이전트에 병렬 배정했다. 두 번째와 세 번째 job에는 앞 구간의 마지막 10프레임을 참고 시트로 제공했다. 참고 프레임은 해당 job의 결과에 넣지 않는다. 각 에이전트는 자신의 구간에서 이전 선택을 이어가며, 작업자 사이의 실제 최종 선택을 실시간으로 공유하지는 않는다. 참고 시트는 경계의 원본 움직임을 이해하는 수단이며 경계 선택이 완전히 같아진다는 보장은 없다.

원본과 후보는 모두 256×191이다. 각 프레임의 후보 순서는 독립 실험과 같은 seed로 섞고 local `P` ID를 유지했다. 같은 exact view에는 시퀀스 전체에서 고정된 `V` ID를 추가해 후보 위치가 달라져도 같은 사진을 추적하게 했다. 기존 검색 순위·점수·독립/기존 선택은 가렸다. 모델에는 형태·극성·윤곽·배치를 우선하되 적합도가 비슷할 때 이전 사진이나 명암·색·배치가 가까운 사진을 고르게 했다. 실제 원본 변화나 형태 대응 손실에는 즉시 바꾸고, 현재 Top-20 밖의 사진은 유지하지 않도록 했다. 사진 유지 시간이나 전환 벌점을 수치로 강제하지 않았다.

`low` reasoning·시트 묶음 읽기·선택 ID만 저장하는 방식은 독립 실험과 같다. 진행 중인 선택을 보존하며 세 작업 모두 100개씩 저장했다. 최초 작업 중 사용자의 속도 요청에 따라 병렬 분할로 전환했으며 첫 작업을 다시 시작하지 않았다. 원격 읽기·유료 API 호출·검색·MS-SSIM 재계산은 없다. 프레임 순서뿐 아니라 고정 사진 ID와 시간적 선택 지침도 함께 달라졌으므로 개선을 무작위 배정 하나의 원인으로 단정하지 않는다.

## 결과

`data/reviews/astra-sequential-300/comparison.mp4`는 왼쪽부터 **원본·독립 Astra·MS-SSIM·연속 Astra**다. 1920×528, 원본 30000/1001fps의 300프레임·10.01초·무음이며 source PTS 순서로 복원했다. 패널별 canonical RGB·표시 크기는 같고 `SEG` 카운터로 병렬 구간을 표시한다. 선택은 실제 장소 사진 한 장이며 보간·크로스페이드·합성·프레임 생략은 사용하지 않았다.

| 지표 | 독립 Astra | MS-SSIM | 연속 Astra |
| --- | ---: | ---: | ---: |
| 인접 299쌍 중 exact view 변경 | 161 | 117 | 76 |
| 한 프레임만 다른 사진으로 갔다 돌아온 A→B→A | 19 | 3 | 0 |
| 같은 view의 최장 연속 유지 프레임 | 26 | 31 | 33 |

연속 Astra는 독립 선택과 180프레임, MS-SSIM과 226프레임에서 다르다. 사진 변경 수는 독립 대비 약 53% 감소했다. 이는 전체 300프레임의 실제 선택 ID에서 계산했으며 두 구간 경계도 포함한다. 동일 view 교체 횟수와 한 프레임 왕복은 깜빡임의 일부 지표이며, 형태 대응이나 시각 품질의 개선을 단독으로 증명하지 않는다. 최장 유지 33프레임은 약 1.10초다. 원본 움직임을 따라가는지는 비교 영상으로 판단한다.

준비는 18.582초, 인코딩은 3.826초다. 최초 에이전트 전달부터 완료 응답 수신까지 관측 512.073초이며, 뒤 두 작업을 전달한 후의 병렬 구간은 322.280초다. 이 시간에는 사용자 지시에 따른 분할 전환·주 에이전트 조율이 포함되고 첫 작업은 먼저 시작했다. 따라서 독립 실험과 같은 조건의 모델 처리율이나 전곡 예상 시간으로 사용하지 않는다. 정확한 구독 사용량은 계측되지 않았다.

## 구현·확인과 산출물

`production/visual.py`에 `--mode sequential`, 연속 구간 배정·10프레임 참고 시트·고정 사진 ID·독립 결과와의 비교·전환 집계를 추가했다. 독립 비교는 같은 production run의 완료 결과를 요구하며 입력이 달라지면 기존 준비 캐시를 덮어쓰지 않는다. 기본 독립 모드의 무작위 배정도 보존한다.

새 구간 배정 계약을 포함한 빠른 테스트 세 개가 통과했다. 실제 300개 선택은 렌더 입력 계약에서 소속·제시 후보·누락 여부를 처리하고 인코더는 정상 완료했다. 기존 다운로드·검색·MSE 선택·느린 전체 테스트는 반복하지 않았다.

산출물 디렉터리에는 `comparison.mp4`, `preview.png`, source PTS·view·장소·좌표·촬영일·회전·선택을 담은 `selected.parquet`, `sheets/`, `jobs/`, `choices/`, `private-map.json`, `manifest.json`이 있다. 실험 ID는 `4292e7b1a6d7992272123fd4c95beb765cc70daee2071f9d78ae2f4b3f07a6f9`다. 시트·판단 원본·출처를 보존하며 모델 응답은 seed만으로 재현된다고 주장하지 않는다.

전곡 확대는 아직 실행하지 않았다. 사용자 재생 평가에서 형태 대응·움직임과 깜빡임의 균형을 판단하고, 병렬 경계 문제가 실제로 보이면 필요한 경계만 후속 보정 대상으로 삼는다.
